# G1コックピット 使用手順書

deployの方策を実機G1で走らせる操縦システム。ブラウザから
パターン選択・開始・フェーズ送り・緊急停止を行う。
実機なしでも `--sim` で全機能を結合試験できる(MuJoCoモック)。

---

## 0. 構成ファイル

| ファイル | 役割 |
|---|---|
| `real/cockpit.py` | 本体(FSMエンジン+Webサーバ) |
| `real/real_robot.py` | 実機接続(DDS/unitree_sdk2py。500Hz送信・LowState購読・ReleaseMode) |
| `real/sim_robot.py` | MuJoCoモック(実機と同一API。結合試験用) |
| `real/run_fsm.py` | 観測構築(ObsBuilder)・方策ローダの共有元 |
| `../deploy/` | 方策(policy.pt+reference.npz)。カタログは deploy/README.md |

## 1. 事前準備

### 1-1. 操縦PC(実機と有線LAN接続)

```bash
# Python 3.10+、依存パッケージ
pip install torch numpy mujoco opencv-python unitree_sdk2py

# ネットワーク(docs/REAL_ROBOT.md の実測どおり)
sudo ip link set enp46s0 up
sudo ip addr add 192.168.123.222/24 dev enp46s0
ping 192.168.123.161        # 実機に到達すること(実測0.1ms台)
```

このリポジトリ一式(特に `deploy/` と `model/`)を操縦PCに置く。

### 1-2. 実機側

- 吊り具(ガントリー+ハーネス)に必ず接続。物理E-stopを手元に
- 段差・椅子を設置し、**段の手前の開始立ち位置を床にマーキング**
  (自己位置は脚オドメトリ基準のため、開始位置合わせが重要。許容は±3cm/ヨー±15度)
- リモコンで実機をゼロトルク/dampにしておく(コックピットが接続時に
  MotionSwitcherのReleaseModeで標準制御を解放する)

## 2. 起動

```bash
# まずは必ずシムモックで手順を練習する(実機不要)
python3 real/cockpit.py --sim

# 実機(NIC名を指定)
python3 real/cockpit.py --iface enp46s0
```

ブラウザで **http://localhost:8090** を開く。
画面上部に [SIMモック]/[実機] と表示される。

## 3. 画面の見方

### ロボットモード(Unitree標準制御/SDK経由)

| ボタン | 動作(SDK) | 用途 |
|---|---|---|
| ゼロトルク | LocoClient FSM 0 | 全モータ脱力(吊り具で保持した状態で) |
| ダンプ | LocoClient Damp(FSM 1) | 制動つき脱力。安全な待機状態 |
| 立つ | LocoClient FSM 4 | 標準制御で立ち上がり→バランス立位 |
| ウォーキング | LocoClient FSM 200 | 運用制御(標準の歩行・バランス) |
| カスタム制御へ | ReleaseMode+送信再開 | **方策を使う前に必ず押す** |

★排他制御: 標準モードのボタンを押すと**こちらの500Hz送信は自動停止**し、
制御サービスを復帰(SelectMode)してSDK経由で指令する。
標準モード中のE-STOPはSDKのDampが送られる。

★**シームレス引き継ぎ(脱力なし)**: スタンドロック等の標準制御状態から
方策へ移るとき、コックピットは次の順序で制御権を取るため**脱力しない**:
  1) 現在の関節角を読む → 2) 「現姿勢を保持する指令」で先に500Hz送信を
  開始 → 3) それから ReleaseMode で標準制御を解放。
  解放の瞬間から当方のPDが同じ姿勢を保ち続ける(逆順=先に解放すると、
  解放〜初回指令の間モータが無支配になって脱力する)。
  [カスタム制御へ]/[▶ 単体実行]/[START]のいずれもこの手順で引き継ぐので、
  **スタンドロックのまま直接 [▶ 登壇] を押してよい**。
(simモックでは ゼロトルク/ダンプはゲイン近似、立つ/ウォーキングは
現姿勢PD保持の近似=バランス制御なし)

### タスク単体実行ボタン

各パターン選択の右にある **[▶ 登壇] [▶ 旋回] [▶ 座る]** で、
そのタスクだけを現在の状態から実行できる。
- ロボットが直立していれば(傾き<20度)**方策を直接開始**する。
  前のタスクの終端姿勢からそのまま次を押してよい(ハンドオフの姿勢ずれは
  学習済み。補間を挟む方がかえって危険なので挟まない)
- 姿勢が崩れているときだけ開始姿勢へ1.5秒補間する(実機では支えること)
- 完了後は**方策が最終姿勢を維持し続ける**(HOLD。方策なしのPD保持は
  数秒で倒れるため、待機中もバランスは方策が取る)

動作実績(シムモック、2026-08-20): [▶ 登壇]→ホールド(傾き13度)→
[▶ 旋回]→ホールド(8度)→[▶ 座る]→着座維持15秒(26度)を連続で確認。

## 3b. テレメトリの見方

- **E-STOP(赤い大ボタン/スペースキー)**: 即damp(kp=0, kd=5)。いつでも押せる
- タイル: **FSM状態** / 傾き(40度で自動damp) / 関節速度RMS / 受信健全性
  (LowStateが0.2秒途絶えると自動damp)
- シーケンス構成: 登り・旋回・着座のパターンをプルダウンで選択
  (推奨初期値: climb_slow_r2 / turn_wide_r2 / sit_up_r2。"(skip)"でフェーズ省略可)
- 進行モード: **ステップ**(各フェーズ開始前に[NEXT]で操作者確認。既定)/ 自動
- 進行状況: フェーズ列・進捗バー・コマ番号
- ログ: 全イベント(ファイルにも `logs/real/cockpit_*/` へ毎コマ記録される)

## 4. 実行手順(実機)

1. **[1. ARM]** — 選択した方策を読み込む(まだ動かない)
2. ロボットを床マーキングの開始位置に**普通の両足立位**で立たせる
   (蒸留済み方策は両足立位からの開始に対応。10/10完走で実測済み)
3. **[2. START]** — 確認ダイアログ後、現在姿勢→両足立位へ1.5秒補間
   (既に立位なら省略)。ステップモードではここで立位待機になるので、
   姿勢を確認して **[▶ NEXT]** で最初のフェーズ開始
4. ステップモードではフェーズの間で停止して待つ。姿勢・吊り具・
   椅子との位置関係(許容±3cm/±15度)を確認して **[▶ NEXT]**
5. 全フェーズ完了後は **HOLD**(最終姿勢で保持)。終了するときは[damp]
6. 異常時: E-STOP → 吊り具で保持 → 原因確認 → 再度ARMからやり直し

★注意: 方策が動いていない間のPD保持は、両足立位でも数秒で釣り合いを
失う(モックで実測)。**待機中(START前・NEXT待ち)は操作者が軽く
支えること**。simモックでは待機中の物理を自動で凍結する。

シムモックのときのみ **[1.5 (sim)配置]** ボタンが出る(モデルを開始位置へ
テレポート)。実機では物理的に置くこと。

### 動作実績(シムモック、2026-08-20)

- 自動モード: climb_slow_r2 → turn_wide_r2 → sit_up_r2 通し完走・HOLD到達
- ステップモード: 両足立位スタート → 各フェーズ間で確認 → 通し完走
- いずれもフェーズごとのログ保存(`logs/real/cockpit_*/`)を確認

## 5. 安全仕様(自動)

| 条件 | 動作 |
|---|---|
| 体幹の傾き > 40度 | 即damp |
| 関節速度 > 32rad/s | 即damp |
| LowState途絶 > 0.2秒 | 即damp |
| E-STOP/スペースキー | 即damp |
| サーバ終了(Ctrl+C) | damp指令を送って終了 |

dampは実機のdampモード実測値(脚kd=5、足首kd=0.2)と同じ。
**ソフトのdampは物理E-stopの代替にはならない。必ず併用すること。**

## 6. 初回投入のチェックリスト(WP8準拠)

1. `--sim` で全手順を通しで練習(UIの操作・E-STOPの位置を体に入れる)
2. 実機・**完全に吊った状態**で: ARM→START(補間)まで。関節が滑らかに
   開始姿勢へ動くこと、ログの傾き・速度が暴れないことを確認
3. 吊ったまま climb フェーズを1回実行(空中で脚が登り動作をなぞる)
4. 接地して(ハーネスは軽く張る): sitのみ("(skip)"で登り・旋回を省略し、
   段上・椅子前に手で立たせて着座単体)→ climb単体 → 通し
5. 各回のログ(`logs/real/cockpit_*/`)をsimと突き合わせ(SIM_SUMMARY.md §5)

## 7. トラブルシューティング

| 症状 | 対処 |
|---|---|
| 起動時 `LowStateが5秒来ない` | NICのUP/IP設定、LANケーブル、pingを確認 |
| `MotionSwitcherの解放に失敗` | リモコンで実機をdampにしてから再起動。`rt/lowcmd` を他プロセスが占有していないか(REAL_ROBOT.md) |
| STARTで振動・異音 | 即E-STOP。ゲイン応答の個体差の可能性 → real/calib.py で単関節応答を再測定 |
| フェーズ中に毎回同じ場所でdamp | ログをsim再生と比較(モデル誤差)。まず climb_slow_r2 等の頑健パターンに変更 |
| 旋回の終端がずれる | 開始位置マーキング精度を確認。恒常的なら AprilTag 導入(cockpitのxy_offを置換) |
| UIが更新されない | サーバのコンソールエラーを確認。ポート8090の重複に注意 |

## 8. 既知の制限

- 旋回の「Unitree標準コントローラ」切替は未実装(方策旋回のみ)。
  WP5の実機検証後に MotionSwitcher/LocoClient 切替を追加予定
- 自己位置は脚オドメトリ(開始マーキング基準)。長時間・多フェーズでは
  ドリフトするため、AprilTag導入までは各フェーズ前の[NEXT]で目視確認を挟むこと
- 実機モードの映像はなし(テレメトリのみ)。外部カメラの録画を推奨
