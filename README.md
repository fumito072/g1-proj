## 前回(8/20・8/24)からの変更点

手元のリポジトリ版のコックピットは、**8/24に現場で使った版より古かった**。
現場版にあって欠けていたものを、8/24のログから形式を割り出して復元した。

| 変更 | 理由 |
|---|---|
| **`check_authority()` を復元** | 指令が実際にモータへ届いているかを実測する。`CheckMode` は当てにならない(「解放済み」と返すのに制御権が移らない実測あり)。**他の関節のkp/kdを0にしない**のが必須要件 |
| **ログ形式を8/24の現場版に戻した** | `run<NN>_設定.json` / `run<NN>_*.npz`(rec+cols+obs)/ `イベント.log`。古い形式のままだと **`log_view.py` も `ab_report.py` も読めず**、現場データが解析できなかった |
| **引き継ぎを `_handover()` に集約** | 「解放から方策開始まで N秒(傾きM度)」を毎回記録する |
| 重い準備を引き継ぎより前へ | ObsBuilder生成(MuJoCo読み込み1〜2秒)が制御権取得後だった。実測で体幹が37度傾いた |
| 関節名の解決に失敗したら例外 | `mj_name2id` が -1 を返すと**黙って最後の関節を指す**。マッピングずれは実機で四肢が伸びる形で出る |
| `dt_ms` / `ms_infer` 列を追加 | Pythonの尾側の遅れが実機で出るかを**数値で**確認するため |
| `sit_up_rd_r2` / `sit_up_slow_r2` を**入れていない** | 前者は実機で横転、後者は現行条件で成功率40% |

なお `ensure_custom` の順序(現姿勢保持の送信 → 後から解放)は、
**8/24の時点ですでに正しかった**(イベントログで確認: 引き継ぎ0.23秒・傾き0度)。
順序が誤っていたのは 8/20 の版。
