# Android から無線でコックピットを操作する(2026-09-04 整備)

制御・推論・DDS は機体(Jetson)の中で完結し、Wi-Fi を渡るのは **ブラウザの画面だけ**
(docs/オンボード運用.md)。Android 側に入れるものは無く、Chrome で開くだけでよい。

★機体の DDS は eth0 にしかバインドされていないので、**PC/スマホ側で制御を走らせる
無線運用は存在しない**(同 §1)。無線 = オンボード実行 + ブラウザ、の一択。

---

## 1. 手順(現場でやること)

```
① 機体の電源を入れ、リモコンで ダンピング(L2+B) にしておく
② コックピットは **機体の電源を入れると自動で立ち上がる**(2026-09-04 systemd 登録。
   LiDAR ブリッジ → コックピットの順。電源投入から約 60〜90 秒で :8090 が待受)。
   手動で立て直したいとき / コードを更新したとき:
     PC(有線/無線どちらでも):  ssh unitree@192.168.179.100 '~/cl-workspace/start_onboard.sh'
     Android(Termux / JuiceSSH 等):  同じコマンド。パスワード 123
   (自動起動が入っているので、このスクリプトはサービスの再起動に化ける)
③ Android を機体と同じ Wi-Fi に接続
     SSID: SPW_X11_fce0f9(モバイルルーター ERC109)   機体 wlan0 = 192.168.179.100
④ Chrome で  http://192.168.179.100:8090  を開く
⑤ Chrome メニュー →「ホーム画面に追加」(次回から1タップ。名前は G1 Cockpit)
⑥ 端末の 設定 → ディスプレイ → 画面消灯 を 10分以上(または 開発者向けオプション →
   「スリープモードにしない(充電中)」)にする   ★下記 §3 の理由で必須
⑦ 画面上部が [実機] と出ていること、右上の受信/送信が OK なことを確認
```

コードを更新したときは PC から `./deploy_to_robot.sh`(有線推奨)で同期して起動し直す。

## 2. スマホ画面の構成

**既定(`/`)は「かんたん画面」**(2026-09-04 新設)。従来の詳細画面は右上の「詳細画面 →」
(`/detail`)。どちらも同じサーバ・同じ状態を見ている。

### かんたん画面

| 欄 | 中身 |
|---|---|
| 上部タイル | FSM / 傾き / 制御(Hz) / **通信**(ブラウザから見た /state の成否) |
| 判定バー | ● 実行してよい / ▲ 要注意 / ■ 実行できません(理由つき)。通信が途絶えていた直後は黄色の帯で「x 秒途絶・途絶中の対応」 |
| 基本操作 | **ダンプ / スタンドロック(FSM4) / 歩行モード(802)** |
| 歩く | **壁の手前で止まる距離**・**横歩きの向きと距離**・障害物の回り込み on/off。**[▲ 前進]**(壁の手前で段階的に減速して停止、壁以外は回り込み)、**[◀▶ 横歩き]**(足踏みパルスで指定距離)、**[左へ5cm][右へ5cm]**(微調整)、**[■ 歩行停止]**。**「前の壁までの距離」**の大きな数字(LiDAR は起動時から自動で読む。赤=停止距離以内、黄=手前0.5m、緑=余裕)。上面図などの可視化は無し(操作者の指示) |
| 座る | 方策の選択、**[▼ 後ろへ5cm/10cm]**(歩行モードで椅子との距離を詰める)、**[着座（この位置でよいか確認）]** → サーバ側の点検(○×△)→ 操作者の3項目チェック → **3秒カウントダウン**(やめるで中止)→ 着座開始 |
| 通信が切れたときの動作 | いまの状態で切れたら何をするかを常に表示(docs/通信途絶時の安全設計_20260904.md) |
| 画面下の固定バー | **E-STOP** と **歩行停止** |

着座の確認で点検する項目: 実行可否(制御ループ・電源・E-STOPラッチ)、傾き 10 度未満、
静止(関節速度RMS 0.10 未満)、内蔵FSM が立位/歩行/UserCtrl、参照との向きのずれ、
LiDAR で後方に座面らしい面が見えるか(参考。頭の LiDAR は後ろ下が死角)、しゃがみ深さ。
× が1つでもあればサーバが開始を拒否する。確認は 30 秒で失効する。

### 着座を一連でやる(スマホ)

```
[ダンプ] → 機体を接地 → [立つ](ロック立位4) → 自立を確認(判定バーが●)
 → [⚡ 立位→UserCtrl→そのまま座る]
   (方策読込 → 802へ遷移 → 7110 → FSM1000確認 → 肘ウィグルで所有確認 → 即開始)

```

## 3. 通信が切れたとき・画面が消えたときに何が起きるか

★2026-09-04 改訂: **通信が切れても damp にはしない**(以前は 8 秒で一律 DAMP → 立位や
着座途中の機体が突然倒れた)。詳細は docs/通信途絶時の安全設計_20260904.md。

| 途絶(8秒)したときの状態 | 機体の挙動 |
|---|---|
| 方策の実行中(着座・登り・旋回の途中) | **最後まで実行**し、方策で姿勢を保持。完了後の自動移行はしない |
| 方策で姿勢を保持中 | そのまま保持(温度をログ) |
| 制御権だけ取った立位・開始姿勢への補間中(方策なしのPD保持) | **内蔵バランス制御へ返して静止**(802 または ロック立位) |
| 十字キーで手動操作中 | 指令が0.5秒更新されない → **速度ゼロ**。内蔵バランスで静止 |
| 自動歩行中 | 中止して **速度ゼロ**。内蔵バランスで静止 |
| 内蔵制御中(立位・歩行モードで待機) | 何もしない(内蔵バランスが支えている) |

damp するのは物理の異常(傾き40度・受信断・送信断など)と操作者の E-STOP だけ。

★**Android の画面が消える = ブラウザのタイマーが止まる = ハートビートが止まる。**
機体は上の表のとおり安全側に倒すが、操作者が介入できない時間ができるので、
§1-⑥ の設定は必須。加えてページ側で次の2段の保険を掛けている
(画面の「画面消灯防止: …」の表示で、どれが効いているか分かる):

1. Screen Wake Lock API — **https か localhost でしか使えない**ので、いまの
   http://192.168.179.100 では効かない(将来 TLS 化したら自動で有効になる)
2. 小さな動画(160×120・2秒ループ・無音)を再生し続ける — Android Chrome は
   「再生中の動画」で端末のスリープを抑止する。ただし Chrome の版に依存するので
   **端末側の設定(⑥)が本命、動画は保険**

★ブラウザは**前面に置くこと**。背面タブや別アプリに切り替えると Chrome はタイマーを
最小1回/分に間引き、猶予をいくら延ばしても途絶する(docs/オンボード運用.md §7-4)。

## 4. 十字キー(手動操作)の仕様

- 内蔵の歩行 FSM(802。だめなら501)に `SetVelocity(vx, vy, ω, duration=0.5秒)` を
  10Hz で送るだけ。バランスは内蔵制御。**方策(lowcmd)は使わない**
- **押している間だけ**動く。指を離す / 指が外れる / 画面が隠れる / 通信が切れる、の
  どれでも 0.5 秒以内に止まる(ブラウザ側とサーバ側の二重のデッドマン)
- 上限: 前進 = 画面の「速度」(既定 0.35 m/s)、後退はその6割、横 0.20 m/s、旋回 0.45 rad/s
- 自動歩行の実行中は十字キーを受け付けない(先に [歩行停止])
- 前後移動中は IMU のヨーで直進を保つ(旧コックピットの実績値 KP=1.6 / 上限0.3 rad/s)

## 5. 2026-09-04 に変えた既定値

| 項目 | 前 | 後 | 理由 |
|---|---|---|---|
| 方策の完了後 | 着座(FSM3)へ自動移行 | **ダンプへ自動移行** | FSM3 自動移行は走行ログに実績が1本も無い。9/3 の全完走回は操作者が手でダンプしており、椅子の上からのダンプは実機で繰り返し通っている。別系統の記録では FSM3 は「床へ倒れ込む着座」(1.1秒でピッチ −27度)で、椅子の上では滑り落ちうる。FSM3 は選択肢として残してある |
| ハートビート猶予 | 8秒(9/3設定) | 8秒(据え置き) | 無線の瞬断を吸収しつつ、UIを失えば止まる値 |

## 6. うまくいかないとき

| 症状 | 見る所 |
|---|---|
| Wi-Fi に繋がらない | 機体の `NetworkManager.state` の `WirelessEnabled=false`(→ `sudo nmcli radio wifi on`)。docs/オンボード運用.md §8 |
| ページが開かない | 電源投入から 90 秒待つ。機体で `systemctl status g1-cockpit g1-lidar-bridge` / `journalctl -u g1-cockpit -n 50` / `~/cl-workspace/cockpit_onboard.log`。自動起動を外すなら `bash ~/cl-workspace/g1_cockpit/real/install_autostart.sh --remove` |
| ボタンが返らない | 画面下の「●処理中」。コントローラーで歩かせた直後は CheckMode が遅い(最大1.6秒) |
| UI が重い(RTT 200ms超) | Wi-Fi 省電力(`wlan0-nopowersave.service` が有効か)。電波 -70dBm 以下なら近づく |
| 「画面消灯防止: ★無効」 | 端末のスリープ設定を長くする。ページを一度タップすると再試行する |
| 十字キーで動かない | 「歩行 準備OK(FSM 802)」になっているか。[歩行モードへ] は **ロック立位(4)** からしか入らない |
