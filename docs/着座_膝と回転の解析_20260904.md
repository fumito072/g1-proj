# 着座の「膝が出る」「回転する」— 実機ログの確認と原因(2026-09-04)

対象: `logs/real/` の実機走行。主に 9/3 の `sit_up_ln23_r2` 11本(全部完走)、比較に
9/2 の ln20(11本)・ln21(19本)、9/3 の rc(8本)。数値はすべて実機ログの実測、
シムは同梱の学習シーン(`model/scene_task.xml`)で方策を閉ループ実行したもの。

図: [着座_ln23_実機11本_時系列_20260904.png](着座_ln23_実機11本_時系列_20260904.png)
(黒=参照、色=実機11本。赤破線=参照が座面に着く 1.84 秒)

再計算: `python3 real/sit_shape.py --policy sit_up_ln23_r2 --all`
(コックピットも走行直後に同じ量をイベントログと[走行の統計]へ出す)

## 1. 確認できたこと(実機)

### 1-1. 膝が前へ出る — 起きている。ただし「開始直後」ではなく「座面に乗る局面」

| 量(ln23・11本) | 実機 | 参照 |
|---|---|---|
| 座面接触の時刻(両膝トルクの落ち込み) | **0.90〜1.22 秒** | 1.84 秒 |
| 骨盤の後退(足首→骨盤、終端) | **13〜28 cm**(中央 19) | 30.5 cm |
| 膝の前方位置(足首→膝、終端) | **+6〜+22 cm**(中央 +13) | −1 cm(スネ鉛直) |
| 膝角(終端) | 95〜110 度 | 80 度 |
| 開始0.5秒の膝の逸脱(RTX側の②指標) | 中央 14 度(9/2 は 18.7) | — |

つまり **参照より 0.6〜0.9 秒早く座面に乗り、その時点の骨盤位置(後退 25〜35cm)で
尻が座面に固定される。参照が要求する残りの後退と股の屈曲(−103度)は物理的に
実現されず、膝が前へ出た姿勢(スネが 20〜30 度前傾)で座り終わる。**
接触後には足首〜骨盤の距離がさらに 10cm 縮む(足が後ろへ滑る、または尻が前へずれる)。

これは「追従不能」ではない。1.84 秒時点で 実測−目標 は股・膝・足首とも −3〜−9 度、
足首トルクは降下中ピーク 25 N·m(定格35)、膝 25 N·m(定格139)。**方策の指令(目標)
そのものが参照から外れている**(膝 +25 度、股 +23 度、足首 −13 度)。

### 1-2. 回転(ヨー) — 起きている。時計回りに 5〜18 度、足が固定では説明できない

| 量(ln23・11本) | 値 |
|---|---|
| ヨー変化(終端) | 平均 −5 度(−18〜+3)。時計回りが 9/11 本 |
| 接触時 / 終端 | 平均 −4.0 度 / −8.2 度(接触後に −4.2 度) |
| 足固定なら 体のヨー = −(左右股ヨーの平均変化) | 予測 ±3 度以内 |
| **足固定で説明できない分(滑り)** | **平均 −7.5 度、11本中9本が同符号** |

股ヨーの方策出力は小さく(平均 ±0.05、11本中1本だけ −0.3)、関節を捻って回っている
のではない。**足が段の上で捻れる/滑る、または座面の上で尻が旋回している**。
ロールは ln20 −10.8 → ln21 −6.4 → ln23 **−4.3 度**(降下中の最小)と改善しており、
終端は +1 度。回転の主体はロールではなくヨー。

### 1-3. 開始位置・設置は原因ではない(実機ログとシムの両方で)

- 実機の開始膝角は 16〜45 度とばらつくが、接触時刻(0.9〜1.2s)と後退(13〜28cm)は
  開始姿勢と相関しない。むしろ伸びた膝(16〜18度)から始めた回のほうが早く座った
- 学習シーンの座面は足首の **2cm 後ろ**から始まり(奥行 36cm、高さ 段+33cm)、
  参照の終端は前縁から 30cm 奥。実機の 13〜28cm 後退でも座面の上にはいる(浅いだけ)

## 2. 原因 — 方策そのものの振る舞い(シムで再現した)

学習シーンで参照の開始姿勢から ln23 を閉ループ実行:

| 条件 | 接触 | 骨盤後退 | 膝前方 | 膝角 | ヨー | ロール |
|---|---|---|---|---|---|---|
| そのまま | **1.29 s**(参照1.84) | **17 cm** | **+16 cm** | 113° | **−12.6°** | −2.0° |
| 椅子を横へ ±3.4 / ±10 cm | 同上 | 10〜22 | +8〜+21 | | −6〜−13 | |
| 椅子を前後へ ±5 / 10 cm | 同上 | 17 | +16 | | −12 | |
| 参照の再生速度 0.8 / 1.2 / 1.4 倍 | 0.8〜0.6 s | 17〜18 | +16 | | −8〜−13 | |
| 座面に水平板(左1.4cm低の傾きを消す) | 1.26 | 15 | +18 | | −12.7 | **−0.1** |
| 板を逆に傾ける(右が低) | 1.25 | 18 | +13 | | −13.0 | +1.8 |
| **脚腰の残差 0.7** | 1.24 | **22** | **+9** | 100° | **−9.6** | −0.2 |

読めること:
1. **早く座る・浅く座る・膝が出る** は、椅子の位置(横・前後)や参照の速さを変えても
   変わらない = **方策が学習した振る舞い**。RTX側がシムで測っている「深さ 134mm」
   (ln22 172mm)は同じ現象で、そちらでは「深さは求めない」と優先度を下げている
2. **時計回りのヨー −12 度** も、左右対称な参照(ln21以降)・対称なシーンで出る =
   **方策が持つ非対称な癖**。椅子の横ずれ・座面の横傾きでは変わらない。
   RTX側が ln23 で観測した「左ロールの偏り再発(左26/右4)」と同根(実機開始バンクと
   左右非対称DRで学習した版から出た)
3. 学習シーンの座面は**左側が 1.4cm 低い**(スキャン椅子の傾き)。シムのロール −2 度は
   これで説明でき、水平にすると消える。実機のロール −4 度(降下中)は別の原因
4. 脚腰の残差を縮めると深く・膝が引っ込む方向へ動くが、残差はバランスの権限そのもの。
   実機開始状態からの試行で 0.6 は転倒した

## 3. 解決に向けて — 何ができて、何が学習側か

### 3-0. ★接触後に膝・足首の残差を抜く(2026-09-04 午後に追加。既定ON、実機未検証)

原因が「座面に乗った後も方策が膝を曲げ足首を引く残差を出し続ける」ことなので、
**座面接触(両膝トルクが降下中ピークの40%を切る)を検知したら、膝・足首の残差倍率を
2秒で0へ落として参照の深い着座姿勢へ寄せる**(旧コックピットの「減衰retarget」を
接触後に当てた形)。学習シーンのシム(参照開始×3シード):

| 抜く関節 / 時間 | 後退 | 膝前方 | 膝角 | 傾き最大 | 尻荷重 | 転倒 |
|---|---|---|---|---|---|---|
| 抜かない(従来) | 23 cm | +14 cm | 107° | 14° | 223 N | 0/3 |
| **膝+足首 → 0 を2秒** | **32 cm** | **+3 cm** | **91°** | 20° | 327 N | 0/3 |
| 膝+足首 → 0.3 を2秒 | 30 cm | +5 cm | 94° | 14° | 251 N | 0/3 |
| 脚腰全部 → 0 を2秒 | 33 cm | +4 cm | 91° | 27° | 320 N | 0/3 |
| 接触後に脚の目標を固定 | 19 cm | +13 cm | 108° | 8° | 140 N | 0/3 |

参照の 30.5cm に届き、スネが鉛直(膝前方 +3cm)になり、体重(350N)のほぼ全部が
座面に乗る。脚腰全部を抜くと参照の前傾相(+20度)がそのまま出て傾き最大27度に
なるので、膝・足首だけにする。コックピットの詳細設定「接触後の膝・足首の残差」
(既定 0 / 控えめ 0.3 / 抜かない)。走行ごとの「検知s」列に接触検知の時刻が出る。
★最初の実機はハーネスで。傾き最大が 14→20度に増えるのは前傾相が出るため(座面上)。

「ちょっと距離があると座れない」(14:37/14:38 の転倒: 座面に届かず前へ 31cm)は
方策が盲目なので詰めるしかない。かんたん画面の [▼ 後ろへ5cm/10cm](内蔵歩行の足踏み
パルスで後退)で椅子との距離を詰めてから着座する。座面の前縁が踵の位置が参照の想定。

### 3-1. コックピット側で今日入れたもの

- **走行ごとの数値化**: 座面接触 / 骨盤の後退 / 膝の前方 / 膝角Δ / ヨー(接触時・終端) /
  滑り が、走行直後にイベントログと[走行の統計]に出る(`real/sit_shape.py`)。
  「膝が出た」「回った」を目視でなく cm と度で A/B できる
- **脚腰の残差スケール**(詳細設定、既定 1.0)。0.85 から、ハーネス必須で A/B する
  ための試験用。バランス権限を削るので**既定では触らない**
- `python3 real/sit_shape.py --all` で過去ログ全部の一覧

### 3-2. 現場で切り分けられること

- **足の滑り止め**(段の上にゴムシート): 滑り分 −7.5 度が消えるかどうかで、ヨーの
  残り(方策の癖)が分かる。接触後に足首〜骨盤が 10cm 縮む現象も減るはず
- **椅子の横ずれ・水平**: シムではヨーに効かなかったので、期待は小さい(ロールには効く)
- 椅子の前後位置: シムでは効かない。「膝が出る」対策にはならない

### 3-3. 学習側(RTX)へ渡す事実(参照・報酬の変更が要る)

RTX側の原則「性能の天井は方策でなく参照(教師)が決める」に沿うと、直すのは次:

1. **早落ち(参照より 0.6〜0.9 秒早く座面に乗る)**: ln23 の学習で "sit_late / hlead" の
   審判を 2 秒緩めた結果、方策は早く座るのが最適になっている。実機・シムとも
   接触が 0.9〜1.3 秒に揃っており、「実機に存在しない審判」ではなく実機で起きている。
   早落ちを 0.3 秒程度までに戻す(または骨盤位置の追従報酬を下降中に入れる)
2. **後退 30.5cm・スネ鉛直の終端は、早く座る方策では届かない**。参照の終端を
   実機の実測(後退 20〜25cm・膝角 100 度前後)へ寄せた版と、1 の修正版の A/B
3. **ヨーの癖**: 左右対称な参照・対称なシーンで −12 度回る。ヨー誤差の報酬/終了条件、
   または左右非対称DRの抽選の偏りを確認(ln24 のバンク鏡像では変わらなかった)
4. **学習シーンの座面が左に 1.4cm 傾いている**(`chair_visual.obj` のスキャン姿勢)。
   水平にすると方策のロール偏りが −2.0 → −0.1 度になる


## 3-0b. 実機結果(2026-09-04 午後): 接触後フェードは実機で失敗 → 既定 OFF に戻した

操作者の報告「左右にぶれる・前に倒れる」。機体のログ(10:26 と 11:46 の 2 セッション、
全 7 本、すべて 395 コマ完走)を比べると、**接触後フェード ON の 3 本だけ**が崩れている。

| 走行 | フェード | 検知(秒) | 骨盤の後退 終端 | 最大\|roll\| | ヨー(走行中の最大) | 終端の膝τ合計 |
|---|---|---|---|---|---|---|
| 10:27 run001 ln23 | 無し | — | **+28 cm** | 4.0° | −15° | 4.7 N·m |
| 10:28 run002 ln23 | 無し | — | +22 cm | 6.4° | −27° | 8.8 |
| 10:30 run003 ln23 | 無し | — | +8 cm | 5.5° | −22° | 5.0 |
| 10:31 run004 ln23 | 無し | — | +18 cm | 3.8° | −6° | 7.3 |
| 11:47 run001 ln23 | **ON(0)** | 0.92 | +22 cm | **33°** | **−96°** | 9.7 |
| 11:49 run002 ln21 | **ON(0)** | 0.94 | **−2 cm(足より前)** | **32°** | **−92°** | 14.3 |
| 11:51 run003 ln23 | **ON(0)** | 1.06 | **−4 cm(足より前)** | 15° | **+42°** | 23.3(脚に体重) |
| 9/3 14:37 run006〜008 ln23(参考) | 無し | — | +18〜22 cm | 4〜10° | −8〜−19° | 5〜14 |

何が起きたか:
- 検知は「両膝トルク合計が、コマ25〜100 の最大値の 40% を下回る(コマ45以降)」だった。実機の膝トルクは
  下降の始まり(0.5〜1.0 秒)で**符号が変わる途中で一度ゼロ付近を通る**(10:26 の 4 本でも 0.5〜0.75 秒に
  2.6〜5 N·m まで落ちる)。ピークも 12〜38 N·m と小さいうちに判定するので、**0.9〜1.06 秒 = 下降の
  入口で「接触」と誤検知**し、そこから 2 秒かけて膝・足首の残差を 0 にした。
- 残差の無い膝・足首は参照をなぞるだけになり、方策のバランス修正が消える。11:47 run001 は検知の直後
  (1.0→1.26 秒)にロールが −7°→−21° へ倒れ、3 秒までにヨーが −93° 回った(回転)。run003 は骨盤が足より前の
  まま(椅子に載っていない)しゃがみで完走扱いになり、完了後の自動ダンプで脚の力が抜けて前へ倒れた(前に倒れる)。
- シムで効いたのは、シムの膝トルクがゼロを通らず、接触で初めて落ちるため。実機では成立しない前提だった。

対応(2026-09-04 午後):
1. **接触後フェードの既定を OFF**(9/3 と 10:26 の挙動に戻す)。選ぶときも、参照の座面到達(1.9 秒)より前
   (コマ 85 = 1.7 秒未満)では検知せず、低トルクが 10 コマ続いたときだけ検知する。
2. **完了後の自動ダンプの前に「座面に載っているか」を見る**: 終端 0.5 秒の両膝トルク中央値が 18 N·m 以上、
   または骨盤の後退が +3 cm 未満なら、自動ダンプを保留して方策で保持し、画面に赤で出す。操作者が目視で
   判断して [ダンプ] / [スタンドロック] を押す。
3. 深く座る手段は「開始位置を椅子に寄せる」に絞る(後退ナッジは 11:47 に 13 秒送って進み 0 = 802 の
   SetVelocity が小さな速度に応じていない疑い。十字キーで前進が動くかを先に確かめる)。

方策の比較(実機ログ全部、完走=395コマ): ln23 34/40(85%)・最大傾き中央 17.6°・ロール中央 4.2° が最良。
dp4 38/53(72%)、ln20 9/11、rc 5/6(傾き 30°)、ar4 7/16、ln21 3/20。**「以前は座れていた方策」= ln23 そのもの**
(9/3 の完走 34 本、10:26 の 4 本)で、今日の差はフェードだけ。


## 3-0c. 実機結果(2026-09-04 12:36): 0.2 秒で「制御周期が遅い」→ダンプ → 立位のまま前へ倒れた

操作者の報告「何回か着座させたが前に倒れる」。12:36 のセッションは 2 本とも **開始 0.2〜0.4 秒で
制御周期ガード(直近 5 コマの中央 44 / 42 ms、限度 40 ms = 23 Hz)が発火してダンプ**している
(`run001` 10 コマ、`run002` 9 コマ。傾きは最大 9° = まだ立っている)。立ったままダンプするので
そのまま前へ崩れる。方策も接触後フェード(OFF 済み)も無関係で、**機体の計算機が遅かった**。

何が違ったか(10:26 / 11:46 は 20 ms で完走、12:36 は 44 ms):
- 12:20 に Jetson を再起動して systemd の自動起動に切り替えた直後だった。systemd のサービスには
  ログインシェルの環境(`CYCLONEDDS_URI` = eth0/wlan0 とユニキャスト設定、`LD_LIBRARY_PATH`)が無く、
  cyclonedds が既定設定で動いていた。また CPU ガバナは schedutil(アイドル 729 MHz)に戻っていた。
  50 Hz の周期タスクはコアの使用率が低く見えるためクロックが上がらず、遅いまま回り続ける。
- IDLE では 49.8 Hz だったので気づけなかった(方策の推論と 500 Hz の lowcmd 送信が始まって初めて遅くなる)。

対応:
1. サービスに **`jetson_clocks`(クロック最大固定)** を ExecStartPre で毎回掛ける。CPU min=max=1984 MHz を確認。
2. サービスの環境にログインシェルと同じ **`CYCLONEDDS_URI` / `RMW_IMPLEMENTATION` / `LD_LIBRARY_PATH`** を入れ、
   コックピットを `Nice=-5`、LiDAR ブリッジを `Nice=5` にした。
3. `start_onboard.sh` / `install_autostart.sh` は、コックピットが走行中(RUNNING/HOLD/制御権あり/自動歩行)なら
   **再起動を拒否**する(再起動で lowcmd が途絶えると機体が倒れる)。
4. 完了後の自動移行の既定を元の **着座(FSM3)** に戻した(9/3 14:20〜14:52 の 8 本が FSM3 で運用され問題なし。
   今朝入れた「ダンプ」既定は、浅く座った機体を前へ崩す)。座面に載っていない疑いがあれば自動移行しない(§3-0b)。

**実測で確定(12:5x)**: 機体で全コアを 729 MHz に固定して方策を 1 スレッド 50 Hz で回すと推論 中央 31.9 ms・最大 64 ms
(12:36 の 30〜57 ms と一致)。最大クロック固定に戻すと 中央 6.3 ms。12:36 の走行ログの `ms_infer` も毎コマ 30〜57 ms
だった(10:26 は 8.6 ms)。再起動前の朝は誰かが `jetson_clocks` を当てていた状態で動いていたと考えられる。
追加の再発防止: 着座前の確認に「CPU クロック固定」の点検(×なら開始拒否)、方策読込時に推論を 4 回暖機
(1 コマ目の 120〜270 ms を走行の外へ出す)。

**確認してほしいこと**: 次の着座の前に、かんたん画面の上部タイル「制御(Hz)」が 49〜50 であること。
走行後のログの「制御周期: 中央20.0ms」を見る。

## 4. 記録(計算方法)

- 座面接触: 両膝トルク合計が、降下中(0.5〜2.0s)のピークの 40% を切った最初のコマ(0.9s以降)
- 骨盤の後退 / 膝の前方: MuJoCo で FK。足首中点を原点、IMU ヨーを除いた水平面で前後距離
  (足首固定の仮定。足が滑ると「後退」が縮む)
- ヨー: IMU 四元数のヨー、開始時基準。滑り = ヨー + 左右股ヨーの平均変化
- IMU 加速度の二重積分で骨盤変位を出す試みは、バイアスで数 m 発散して使えなかった
