# 後ろ向き段差登りの本流コックピットへの移植(2026-09-07)

元: `G1_後ろ向き段差登り_一式/`(2026-08-21、Mac 用の実行系 `06_コード/5_実機/g1_live/`)。
人動画(3 視点)→ SMPL → IK → 整形した教師 `back_climb_clean.npz`(362 コマ、段 0.210 m)で
段階学習した方策(段階 B: 押し外乱つき 95%)を、本流の `run_fsm.py` / `cockpit.py` から動かせるようにした。
**実機では未実行。**

## 何を足したか

| ファイル | 内容 |
|---|---|
| `deploy/climb_back_B/`, `deploy/climb_back_A/` | `policy.npz`(numpy 重み、183→512→256→29)・`reference.npz`・`meta.json`。B が既定候補(A は外乱なし 100%、B の比較用) |
| `real/back_climb.py` | `NumpyPolicy`(観測正規化+MLP)、`BaseEstimator`(脚オドメトリ)、`BackClimbObs`(183 次元) |
| `real/run_fsm.py` | `Policy` が `policy.npz` を読めるように(family="back_climb")。行動ローパス 0.5、区間終端 260 で凍結(`n`=261) |
| `real/cockpit.py` | `make_obs_builder`(系統で観測の組み立て器を切替)、`climb_stand` を使わない、観測に tau/加速度を渡す、モックの配置と物理設定 |
| `real/real_robot.py` / `sim_robot.py` | `imu_accel()`(加速度計)。モックは `configure_physics("back_climb")` で学習環境の衝突・摩擦に切替 |
| `sim_compare.py` | 変更なし(`--pitch-bias-deg` は着座用) |

deploy の並びは名前で判定しているので `climb_back_*` は「登り」の選択肢に自動で入る(詳細画面の登り select)。
既定の登りは従来どおり `climb_slow_r2`(前向き)。後ろ向きは操作者が選ぶ。

## 観測(183 次元)の再現 — 学習環境との突き合わせ

学習環境 `motion_env.py`(一式の `06_コード/4_学習/rl/`)を真の観測で駆動しながら、同じ状態から私の
`BackClimbObs.build` を計算して成分ごとに比べた(`scratchpad/ana/bc_parity.py`)。

| 成分 | 差(中央値 / 最大) | 備考 |
|---|---|---|
| 体の向き・角速度・関節角/角速度・参照差・進捗・重心/足の体幹座標 | 0 | 運動学だけなので一致 |
| 高さ(推定) | 0.001〜0.009 / 0.04 m | 脚オドメトリ |
| 速度(推定) | 0.01 / 0.35 m/s | 接地の切替と着地の瞬間に差 |
| 水平位置(推定) | 0.02〜0.04 / 0.10 m | 積み上がり |
| 接地フラグ | **一致(直した後)** | 下記の癖 |
| 荷重配分 | 参照の位相表で代用 | 下記の癖 |

**学習環境の癖 2 つ**(方策はこの値で学習しているので、実機側もこの意味で作る):
1. 接地フラグは**床との接触を数えない**(`robot_bodies` に world が入り、足×床が「ロボット同士」扱い)。
   段・椅子の geom との接触だけが 1。→ 「足が段(地形 0.1 m 超)に乗っている」ときだけ 1 にする。
2. 荷重配分(左足の割合)は、段の上で左足の内部接触力(1700 N 級)が二重に数えられて 0.9 前後になる。
   実機で測れる量ではないので、学習環境を真の観測で駆動した 6 本の位相ごとの中央値 `ref_load`(reference.npz)
   を両足支持のときに使い、片足支持は接地の確信度で 1/0。

## 成功率(学習環境で閉ループ、20 本、`climb_back_B`)

| 条件 | 真の観測 | 私の観測 |
|---|---|---|
| 押し外乱なし | 20/20 | **19/20** |
| 押し外乱あり(毎秒 0〜0.5 m/s、学習時の DR) | 15/20 | 5/20 |
| 静止から開始(実機と同じ。学習環境は参照の関節速度で始める)・外乱なし | 20/20 | 19/20 |

推定器の調整で決まった: 速度は**接地足の脚オドメトリを全面的に信じる**(`kv`=1.0。元の 0.6 では 13/20)。
位置の錨の重みは 0.5 のまま(1.0 にすると 13/20)。IMU の加速度で予測は残す(外すと 14/20)。
成分の切り分け(真値に置き換え): 速度を真値にすると 20/20、高さ 16/20、水平位置 12/20 → 速度の質が支配的。
押し外乱は学習環境では体幹速度を瞬時に書き換える(加速度計に出ない)ので推定が追えない。
実機で毎秒 0.5 m/s の外乱は無いが、モデル誤差はある。**ハーネス必須。**

## コックピットのモック(sim_robot)での確認

- モックの既定物理(自己衝突なし・摩擦 1.0・condim 3)では登り切れない(同じ目標を流す 200 コマの比較で
  関節が 0.3 rad ずれる)。学習環境の衝突設定(脚・胴は環境+自己、腕は自己のみ、椅子と床は環境側、
  摩擦 0.85、condim 4)に切り替えると一致(200 コマで z 0.816 vs 0.855)。`configure_physics("back_climb")`。
- 学習環境の初期状態をそのまま写すと 6/8。モックの `place()`(静止)からは成功率が下がる回があり、
  原因は未特定(閉ループの感度)。学習環境での結果を正とする。

## 実機で試すときの手順と前提(★未検証)

1. 段は高さ **0.21 m**(学習)。椅子の土台(実測 0.222 m)ならほぼ同じ。踏み面の奥行 0.38 m。
   実物 0.26 m なら教師の作り直しが要る。
2. 立ち位置: 参照の開始は、段の前縁(y=−0.49)から**骨盤が 7 cm 手前**(y=−0.562)、背中を段に向ける。
   ほぼ「踵が段の前縁に触れる」位置。LiDAR は後ろ下が死角なので目で合わせる。
3. 詳細画面: 登り = `climb_back_B` → [スタンドロック] → [開始姿勢へ climb](参照 fr0 へ 1.5 秒で寄せる。
   両足立位、膝 24°)→ [▶ 登壇]。ゲインは学習値(脚 kp 400/kd 12)で公式例の 4〜6 倍固い。
   元の実験で剛性 0.3 では膝が支えられず後傾して転倒しているので、下げない。
4. 260 コマ(5.2 秒)で登って直立、以後は 260 で凍結して方策で保持(HOLD)。次の段(旋回・着座)は
   元の一式に `back_climb_sit`(派生)があるが未移植。
5. 中止条件は本流のまま(傾き 40°、制御周期、NaN)。最初は軽い吊りサポート下で。

## ★実機で始められない理由(2026-09-07 昼、追記)

かんたん画面に「後ろ向きに段を登る」(点検 → 3 秒後に開始、着座と同じ UserCtrl → すぐ方策)を付けて、
実機の立位姿勢(スタンドロック直後の関節角、9/7 run001)から始めた場合を学習環境で測った:

| 開始のしかた | 成功 |
|---|---|
| 着座と同じ(すぐ方策、参照ブレンド 0.5 s / 1.0 s) | 0/20 / 0/20 |
| 方策を動かしたまま参照を fr0 に固定して 2 秒ならす | 0/20 |
| PD だけで参照 fr0 へ補間(1.5 / 3 / 6 / 10 秒)してから方策 | すべて 0 — **補間中に倒れる**(傾き 94°、体が 109° 回り 0.66 m 動く) |
| 立位に近い参照コマから開始 | 近いコマ(差 14°)は登り切った後の 246〜257 しか無い |

原因: 教師の開始姿勢が **右股ヨー −52°・右股ロール −18°・左股ヨー −18°**(人の動画の初期の立ち方の取り込み)で、
足を床に着けたまま通常の立位からこの形へ回すと足が滑って倒れる。学習環境は最初からこの形に置くので問題が出ない。
方策は開始姿勢 ±1°(関節速度 0.05 rad/s)しか見ていないので、通常の立位からの開始は分布外(0/20)。

**結論**: いまの方策(段階 A/B)は、通常の立位から始める実機運用には使えない。かんたん画面の点検は
「開始姿勢との差 ≥ 35°」を × にして始めない(実機の立位では 51°)。
**次の一手(学習側)**: 教師の先頭に「通常の立位(股ヨー 0)から動画の立ち方へ移る 1〜2 秒」を足すか、
`clean_feet.py` で股ヨーの初期オフセットを消してから段階学習をやり直す。観測・実行系(本流への移植)はそのまま使える。
