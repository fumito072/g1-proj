# 6. ファームウェア世代とSDK(2026-08-26 の整備)

FW更新で **FSM番号と受け渡しの公式APIが変わる**。ここは全部自動追従にしてある。

## 6.1 世代の自動判別(`deploy/fw_profile.py`)

**ロボットには一切指令を送らない(読むだけ)。** ランナーは実機実行のたびに再判別する。

1. `rt/sportmodestate`(FW 1.5.1+ のみ配信)を1.5秒購読。届けば**新FW**確定
   型は `unitree_hg::SportModeState_ { fsm_id, fsm_mode, task_id, task_time }`。
   vendor版SDKには go 側の別物しか無いので **hg型を自前定義**して購読する
   (`fsm_mode` 0=静的=モード切替可 / 1=動的=切替ほぼ不可)
2. 届かなければ `GetFsmId`(7001)。**200=旧FW** / 500,501,801,802=新FW
3. 決め手なし → **旧FWとして振る舞う**(実績側に倒す)

> ★実測 2026-08-26: **FW 1.5.3.8** では `rt/sportmodestate` と `rt/user_lowcmd` が
> 配信されているのに、自前定義IDLでの購読はデータが来なかった(実物の型と構造が合わず黙って不成立)。
> → 型の中身に依存しない **「DDS組み込みトピック(DcpsPublication)でのトピック名の発見」**が
> 最も確実な新FWの証拠になる。

現在の判別結果 `artifacts/fw_profile.json`:
```json
{"世代":"新","運動制御FSM":500,"sportmodestate":true,
 "判別根拠":"新FWトピックを発見: ['rt/api/sport/request']","時刻":"2026-08-26 15:53:28"}
```
手動上書きは config `安全.FW世代`("auto"/"旧"/"新")。
コックピットの **「FW診断」**ボタン(`fw_check.py`)が同じ判別 + lowstate/mode_machine/
サービス名の棚卸しを行う(更新がちゃんと入ったかの確認用)。

## 6.2 FSM表

| 意味 | 旧FW(実測) | 新FW(公式表) |
|---|---|---|
| ゼロトルク | 0 | 0 |
| ダンピング | 1 | 1(常に遷移可) |
| スクワット | 2 | 2 |
| 着座(床へ) | 3 | 3 |
| ロック立位 | (4=立ち上がり) | 4 |
| メイン運動制御(歩行/バランス) | **200**(500は無視される) | **500** / 501(腰3DoF歩行) |
| 走行 | ― | **801 / 802**(29dof) |
| 伏せ⇄立ち / バランススクワット | ― | 702 / 706 |
| 内蔵mimicモーション | ― | **550 + motion_api_id** |
| UserCtrl(自作制御所有中) | ― | **1000** |

`FSM_START` はランナーもコックピットも起動時に fw_profile から解決する(直書きなし)。

**新FWの遷移の作法**(2026-08-26実測+コミュニティ):
- 立位で足首まで固めるのは**ロック立位(FSM4)**
- 0/1 から直接 歩行(500) は拒否されることがある
  → **ダンピング(1) → ロック立位(4) → 歩行(500)**(だめなら501)の順で通す
  → コックピットの「歩行開始(自動)」が読み返し確認つきでこの順を実行する

**新FWのリモコン操作**: L2+R2=デバッグ(脱力) / L2+B=ダンピング / L2+UP=レディ / R2+A=運動制御開始

## 6.3 受け渡し方式(config `安全.受け渡し方式`)

| | `"release"`(既定) | `"user"`(新FW専用) |
|---|---|---|
| 機構 | MotionSwitcher の `ReleaseMode` | 公式 **User Development Mode** |
| 入り | 静止待ち→latch→即Release(窓 実測**0.20秒**) | latchを `rt/user_lowcmd` へ流してから `SwitchToUserCtrl`(7110)。**切替までは無視されるので競合窓ゼロ** |
| 返し | 立位へ戻す→SelectMode("ai")→FSM確認→kp抜き | `SwitchToInternalCtrl`(7111)。復帰モード 0=LAST / 1=PASSIVE / 2=WALKRUN。非常時は強制PASSIVE |
| 世代 | 両世代で動く(実績あり) | 新FWのみ。旧FWと判別されたら起動時に中止 |

公式の警告(そのまま従う):
> 歩行モードとの受け渡しでは、**自作制御の最初と最後を標準立位**にすること。
> さもないとロボットが制御を失うことがある。

## 6.4 UserCtrl(7110/7111)で実機に判明したこと

- **vendored SDK の LocoClient は 7110/7111 を登録しておらず、`_Call` が
  ロボットに送らずに 3103(API_NOT_REG)を返す**(実機12:43)
  → `_RegistApi(7002/7110/7111)` を自前で追加登録(登録だけなら旧FWでも無害)
- **`{"data": false}` は code=0 を返すのに実際には切り替わらない**(実機12:48/12:54:
  全パラメータ変種でACKのみ・関節が1本も動かず内蔵が立位保持を継続)
  → 呼び出し側は必ず**所有確認(ウィグル)**を行う
- **歩行(500/501)は静止していても「動的(fsm_mode=1)」扱い**で、`SwitchToUserCtrl` は
  code=0 を返しながら**黙って無効**になる(公式doc「状態が不適切なときはモード変更を禁止する」)
- **このFWは 501→4(ロック立位)を拒否する**(実測13:01、8秒不変)
- ★**調査確定(2026-08-26)**: 公式の「WALKRUN mode」は歩行(500/501)ではなく
  **走行制御(801、ai_sport 8.6以降は802。リモコン R2+A の通常起動)**。
  初期テンプレは `fsm_id == 801` でゲートしていた。当機の実測拒否はすべて 501/4/1 からで、
  **802からは未試行**だった → **実機15:22で 802 からの進入が実証された**
  (501→802 はプログラム遷移が通り、802の静止立位から 事前ストリーム+7110 で FSM=1000。往復も実証)
- **ロック立位(4)からは走行へ自動遷移しない**(実機13:58: WALKRUN(2)がこのFWで**802(走行)**に入り、
  吊り機体が空中走行で暴れ、ゼロトルクも802から拒否された)
- 予備経路: **ダンピング経由**(SetFsmId(1)→7110連打)。実証済みだが**脱力窓0.27秒**がある
- 新FWのrelease方式は解放の競合窓が **0.50秒**に伸びる(実機12:35)
- 新FWでは **501(腰3DoF歩行)も正当なバランス立位**。これを「立位でない」とみなして
  501→500 を強制し、**拒否されたのに失敗のまま進んで**受け渡した結果、静的保持で後傾31度になった
- 健全な中止(事前検査ではじいただけ)なのに PASSIVE 返却で脱力していた(実機15:44)→ 経路を分けた
- `SelectMode` 直後は FSM=0(ゼロトルク)になりやすい(実機16:18)
- **Sit(FSM3)は使わない** — 床へ倒れ込む着座で、実機16:35は 1.1秒でピッチ −2度 → −27度

## 6.5 公式 mimic テンプレとの対応(`docs/参考_unitree公式mimicテンプレ/`)

出典: `unitreerobotics/unitree-app-templates`(UniStore公式アプリの雛形)。
**自作RL方策を新FWの実機で走らせる Unitree公式の現行リファレンス**。

| 公式テンプレ | この実装 |
|---|---|
| 進入は歩行(WALKRUN)から 7110。FSM1からはエラー | ★当機FW 1.5.3.8では歩行からの7110が無効(実測)なので**当面ダンピング経由**で代替。FW更新で歩行直接進入(第1段)が自動的に有効になるはず |
| 切替後0.1秒で `GetFsmId==1000`、さらに**毎秒再確認**し1000でなくなったら即Exit | 同等の所有確認を実装 |
| 切替の瞬間から**RL方策が制御**(静的保持の時間なし) | 同じ方針に変更(`確認秒数_user進入 = 0.0`) |
| 50Hz、目標角のみ(dq=0, tau=0)、kp/kdは学習時ゲイン | 同じ(500Hzで線形補間して送出) |
| bad_orientation で Passive へ自動フォールバック | 転倒検知→脱力/内蔵返却 |
| ループ遅延は警告のみ | こちらは**5連続で中止**(+開始猶予) |

## 6.6 内蔵mimicモーション(`artifacts/mimic_motions.json`)

新FW(1.5.x)の内蔵モーションライブラリ。**立位からバランスを維持したまま**内蔵制御が
全身モーションを再生する公式機構(`GetMimicMotion`)。呼び出しは `SetFsmId(550 + motion_api_id)`。
公式注意: `The Robot must be in a stable state (e.g., standing)`。

`mimic_list.py` は**一覧の取得だけ**を行う(モーションは実行しない)。

- **79種**、API ID **101〜605**
- 起き上がり系: 401 `get_up`(仰向け, 3.08秒) / 402 `lie_down` / 403 `facedown_get_up`(5.48秒)
- 挨拶・ジェスチャ: `hello_left/right/both_hand` / `bow` / `shrug` / `akimbo` / `make_heart_upon_head` ほか
- ダンス・演武: `vq_POPPING*`(18〜38秒)/ `vq_YSKJ_*` / `yingbin`(42.24秒)
- 101 `stance`(0.02秒)= 基本立位

コックピットの「全身動作(内蔵バランス制御)」パネルから一覧表示・シーケンス実行ができる。
