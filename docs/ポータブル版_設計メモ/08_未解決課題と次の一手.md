# 8. 未解決の課題と次の一手

## 8.1 ★足首トルクが足りない — 二歩目に進めない直接原因

実機13:55(2026-08-17)のログ:

| step | 参照fr | pitch | 状況 |
|---|---|---|---|
| 0 | 4 | −0.065 | 参照(−0.04)とほぼ一致 |
| 18 | 22 | −0.158 | まだ床の上なのに後傾が進む |
| 30 | 34 | −0.226 | 一歩目の直前 |
| 48 | 52 | **−0.444** | 転倒検知 |

**関節はよく追従している**(足首L 参照−0.400 対 実測−0.421、誤差0.02rad)。
**行動の飽和は0%**で方策は暴れていない。それでも体幹が後傾する
= 関節角が正しいのに姿勢が違う = **足が地面に対して踵側へ転がっている**。

トルク推定 `|kp(qt−q) − kd·dq| / 上限`:

| 関節 | 最大 | 95%超の時間 | 上限 |
|---|---|---|---|
| right_ankle_pitch | **1.87** | 8% | 50 Nm |
| left_ankle_pitch | 1.40 | 8% | 50 Nm |
| right_shoulder_roll | 1.82 | **58%** | 25 Nm |
| left_wrist_yaw | 1.80 | 50% | 5 Nm |

重心を前へ引き戻すのに50Nmでは足りず、飽和して踵側へ転がる。
関節誤差による重心のずれは前後 **−3.2mm**(うち腕の垂れ −2.3mm)と小さく、
**姿勢の誤差ではなく足首の能力が足りない**。

### 対処の方向(効きそうな順)
1. **開始位置を2〜3cm前へ** — 重心が足首より後ろにあると常に前向きトルクが要る
   (コックピットの段差距離表示で位置合わせ)
2. **腕の垂れを減らす** — 肩ロールが58%の時間トルク上限。参照姿勢を保てていない
3. **段の高さを実測に合わせる** — 参照は 0.204m 前提。実物との差は未計測

## 8.2 構造的に残っている差(README §8)

| 項目 | 内容 |
|---|---|
| **位相が経過時間で進む** | 関節目標・先読み87次元・接地フラグはすべて「何ステップ目か」で進む。実機が遅れても参照は待たない。**実状態への同期機構は無い**(学習側の変更を伴うため中期課題) |
| **椅子のスケール0.85倍** | シムの段0.204m。実物が等倍なら0.240m相当。水平寸法も18%違う |
| **`step_plate` はシム専用** | 元メッシュはy方向に38.5mm傾き、板が無いと足の4接点のうち2点しか接地しない。**実機の段に同じ平面が無ければ学習が成立した地面ではない** |
| **PD・遅延の未ランダム化** | 学習はゲインも遅延も摩擦もランダム化していない |
| **足裏力センサが無い** | 実機の `unitree_hg LowState_` にフィールドが存在しない。接地・荷重は推定 |
| **IMUの取り付け位置が未確認** | モデルに `imu`(骨盤原点)と `secondary_imu`(waist_roll_link +13.8cm)の2つ。腰上なら腰3軸ぶんの系統誤差。`compare_sim_real.py --live --active` で判定できる |
| **開始位置は目視** | 段までの距離・角度を測る手段が無い。水平位置は脚オドメトリの積分でドリフトする |
| **B段の前進0.32m** | A終端→C開始は「その場旋回」ではなく**0.32m前進しながら約160度旋回**。距離を測れないので既定は旋回のみ |
| **`parity_test` は推定器を通らない** | 真のシム状態で観測を組むので、高さ推定・脚オドメトリ・ヨー補正のバグは検出できない |

## 8.3 未検証のまま残っているもの

1. **後ろ向き方策の実機検証そのもの**
   `back_climb_best_B` はシムで段階B基準を95%で満たすが、**実機での検証はこれから**。
   前向きで二歩目に進めなかった足首トルクの問題は、後ろ向きでは踏み込みの向きが変わるので
   **実機で測り直す必要がある**
2. **受け渡し後の傾きが実際どこまで収まるか**
   15度→31度の転倒が latch順序の修正だけで消えるかは**まだ分かっていない**。
   残っていれば原因は「内蔵バランスが動的に立たせていた姿勢を凍結したこと」そのもの(=倒立振子)
3. **ハイブリッド着座** — 正直なシム検証で16/20。`probe_hybrid.py` が全シード完走するまで
   ランナーが実機実行を自動ブロックする
4. **UserCtrl(新API)経由の受け渡し** — 802からの往復は実機15:22で実証されたが、
   これで着座を通した実績はまだない。**最初の実機試験は必ずハーネス+片手にリモコンE-stop**
5. **B段(段上での旋回)** — 実機未検証。段の上面は約0.72m×0.40m。
   床で30°→90°→159.4°の順に検証してから

## 8.4 次の一手(優先順)

### 実機側
1. **段の高さ・椅子の位置を実測する**(0.204m前提 / 座面0.5525m前提が合っているか)
   — 別系統のログ解析でも「参照が想定する設置寸法が現場未実測」が最大の未確認要因になっている
2. 後ろ向き `back_climb_best_B` を **A段だけ**、ハーネス付きで回す
   → ログの「掴み→解放の窓」「解放直後の傾き」「飽和した関節 上位3つ」を見る
3. 開始位置を2〜3cm前にずらして足首トルクの飽和が減るか測る
4. `compare_sim_real.py --live --active` で **IMU取り付け位置と遅れを確定**させる

### 学習側
1. **γ を課題長に合わせる**(着座0.995 / 段差登り0.997)。現行 γ=0.97 は0.67秒しか見ていない
2. **観測に前回の行動を追加**(現状 `r_smooth` が非マルコフ)
3. **MjModel をプロセス内共有**にして 128〜256環境を載せる(+36%、RSS 1/3)
4. **段差登りに押し外乱0.3の段階Bを回す**(現状63%、失敗はほぼ上半身ロール12度超の制約違反)
5. **椅子の姿勢・開始姿勢のランダム化**(前後±5cm / 左右±3cm / ヨー±10° / 座面高±2cm、脚腰±0.20rad)
6. **膝の左右差**を報酬か終了条件に入れる
7. mjlab(MuJoCo Warp)へ移行するなら、**制約(終了条件)を落とさないこと**。
   `r_sit`+尻荷重15%未満0.5秒で失敗 / `r_plant`+足浮き0.6秒で失敗 / `r_roll`+ロール12度で失敗 —
   **罰だけでは空気椅子・片足立ちは消えなかった**

## 8.5 このパッケージから学べる一般則(横展開できる知見)

1. **sim2real の失敗は方策より先に「制御権の受け渡し」を疑う。**
   ゼロゲインの送信ですら内蔵制御と競合する。所有フラグで機械的に排他する
2. **「止めろ」というAPIが本当に止めるとは限らない**(`StopMove()` の実体は `SetVelocity(0,0,0)`)
3. **偏差ゼロの追従(follow)では kp をいくら上げても支えにならない**(効くのは kd だけ)
4. **静止して待つのは不安定**。倒立振子は「止める」のではなく「動かし続ける or 即中止」
5. **罰(報酬)だけでは悪い解が残る。制約(終了条件)にして初めて消える**
6. **罰は線形に。** 飽和する指数型は勾配が消えて学習しない(2回踏んだ)
7. **観測は閾値を合わせるのではなく、定義そのものを共有する**
   (実機側でもMuJoCoを持ち `mj_forward` して学習時と同じ関数で接地・重心を求める)
8. **シムが何度完走しても実機経路のバグは出ない。** 静的検査(pyflakes)を毎回通す
9. **検証と設定の指紋を突き合わせ、一致しなければ動かさない**(warp指紋 / hybrid_probe スタンプ)
10. **「見せかけの20/20」に注意。** 同一ロールアウト×20を多様性と誤認していた
11. **ノートPCはACアダプタを挿す。** バッテリー駆動だとガバナ performance でも800MHzに落ち、
    制御周期が17〜33Hzまで落ちる
