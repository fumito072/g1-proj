## 5.2 ★2026-08-24: 前向き → 後ろ向きへの切り替え(旋回工程が消えた)

前向きで登ると、登り切った時点で椅子に**正対**しており、着座開始まで旋回が必須だった。

| | 登り終わりのヨー | 着座開始のヨー | 差 |
|---|---|---|---|
| 前向き `climb_hold` | +110.6度 | −90.0度 | **200.6度** |
| **後ろ向き `back_climb`** | **−90.9度** | −90.0度 | **0.9度** |

旋回はG1内蔵歩行に任せるしかなく、**その間はEnter停止も転倒検知も効かない**
(止める手段がE-stopだけ)という、この手順で一番危ない工程だった。
後ろ向きにすると**工程ごと消える**。既定の段は `AC`。

**残る差**: 後ろ向きの終端は (x+0.027, y−0.274)、着座の開始は (x+0.025, y−0.120) で
y方向に **0.154m** の差。座標系はC段の開始で取り直すので観測は成立するが、
**椅子との物理的な距離は変わらない** → C段の前に目視で確認。

### 使う資材の対応

| | 前向き(旧) | 後ろ向き(新) |
|---|---|---|
| 参照 | `motions/climb_hold.json` | `motions/back_climb.json`(**362コマ**) |
| 区間 | 0–375 | **0–260**(学習側の段階B) |
| 方策 | `climb_v2_best_A.pt` | **`back_climb_best_B.pt`** |
| 骨盤高さ | — | 0.780 → 0.987 m |

### ★行動ローパス(これが無いと動かない)
後ろ向きの方策は**学習時に環境側で行動ローパス**(`act_beta=0.5`)を掛けて学習している。
外すと段階Bの合格率が **95% → 0%** に落ちる(実測)。
実機では `config.json` の `安全.行動の平滑化係数 = 0.5` が同じ式を担う。**下げてはいけない。**

## 5.3 前世代の到達点(`docs/STATUS.md`、30試行の実測)

| 課題 | 外乱なし | 外乱0.3m/s | 補足 |
|---|---|---|---|
| 段差登り+5秒静止 | **100%** | 70% | 両足が段上100%、上半身ロール0.3度 |
| 椅子に座る | **100%** | **100%** | 尻の接触99%、尻の荷重263N(体重344N) |

### 解決済み: 着座の「空気椅子」
修正前は静止区間で尻が座面に接触しているコマが**34%**、尻の荷重の中央値**0N**。
方策は骨盤を参照より**53mm高く**保ち、体重の全てを脚で支えていた。
倒れないので「完走100%」と出るが、**座る動作になっていなかった**。

対処は報酬と**制約**の両方:
1. `r_sit`(重み0.20)— 参照が座っているコマで尻が座面から受ける荷重を評価
2. 尻が体重の15%未満しか受けない状態が0.5秒続いたら**失敗**(`SIT_LATE_STEPS`)

| 指標 | 修正前 | 修正後 |
|---|---|---|
| 尻の荷重(中央値) | 0N | **275N**(体重344Nの80%) |
| 尻が接触しているコマ | 34% | **99%** |
| 骨盤の高さ | 0.751m | **0.699m**(参照0.698m) |

> **罰だけでは他の項で稼いで悪い姿勢が成立する。制約(終了条件)にして初めて解決した。**
> 片足立ち・上半身の傾きも同じ手法で解決している。

### 設計判断の根拠(実測)
- **段差の踏み面に平らな板(`step_plate`)を追加**: 元メッシュの上面はy方向に38.5mm傾き、
  足裏の範囲だけでも10mm変化。足の4接触球のうち2つしか接地せず支持多角形が線状になり必ず倒れた
- **座面には板を敷かない**: 一度敷いたら元メッシュの座面(0.530〜0.551m)より約80mm高くなり、
  股関節リンクが板と干渉して体重の**18〜25倍(6000〜8700N)**の反力で弾かれた
- **押し外乱は0.3m/sが上限**: 捕捉点 v/√(g/h) が足裏長(約100mm)を超えると
  踏み替えなしでは原理的に回復できない(0.3→93mm / 0.4→125mm / 0.5→156mm)
- **静止中の姿勢は物理で選んだ**: 28通り中19通りが成功し、最も揺れの小さい
  「前傾12度・骨盤を60mm前」を採用。重心が支持多角形の内側にあるのは必要条件にすぎず、
  余裕25mmでも倒れた

### 評価の落とし穴(実際に踏んだもの)
1. **エピソード長の打ち切りを「完了」と数えていた**(上限6秒固定で9.2秒の課題が打ち切られ成功扱い)
2. **評価と学習で外乱条件が違っていた**(失敗率12%に対し評価58%)
3. **接地判定が30mmの浮きを見逃していた**(`_contact_state()` は30mm以内を接地とみなす)
4. **`_load_ratio()` は接触力ゼロのとき0.5を返す**(片足立ちが「均等」に見える)
5. **終端の一瞬しか見ていなかった**(静止の評価は区間を通して測る)

## 5.4 座る速さ(時間軸の伸長。再学習は不要)

参照の下降(原コマ32〜92)は素のままだと **1.50秒で0.28m** 落ち、関節速度は最大 **1.39rad/s**。
実機には速すぎるので**下降のコマだけ時間軸を伸ばす**。
方策は残差方策(目標角 = 参照 + 行動×0.7)なので、参照をゆっくりにすれば動きもゆっくりになる。

| 速度倍率 | 下降 | 参照の最大関節速度 | シム20シード完走(`sit_v1_best_S`) |
|---|---|---|---|
| 1.00(素) | 1.50秒 | 1.39 rad/s | 20/20 |
| 0.70 | 2.12秒 | 0.97 rad/s | 20/20 |
| 0.65 | 2.28秒 | — | 20/20 |
| 0.60 | 2.46秒 | — | 19/20 |
| 0.55 | 2.66秒 | — | 6/10 |
| 0.45 | 3.24秒 | — | 1/10 |

崩れ方は「下降の後半で傾きが発散して転ぶ」。
**この方策は中腰を『通過する』ようにしか学習していない**ので、そこに長く留まらせると保てない。

実装は `rl/timewarp.py`。新コマ n → 原コマ u(n) の写像を作り、参照配列一式を取り直す。
区間の縁は余弦で繋いで参照速度が階段状に跳ばないようにする。
**観測の「進捗」スカラーだけは原参照の位相(`ref_phase`)を渡す** —
ここを新しい時間軸のまま t/ref_len にすると同じ姿勢でも値が変わり、方策から見て未知の入力になる
(実測: 進捗が最大0.13ずれ、0.55倍速の完走が 6/10 → 2/10 に落ちた)。

`着座域` のコマ番号は**原参照(250コマ)のまま**書き、ランナーが `Policy.frame()` で
再生中のコマ番号へ読み替える(原45 → 再生54)。

## 5.5 `sit_soft_v2` — 座面の衝撃を半分にした追加学習

`sit_v1_best_S` から **4.01Mステップ**追加学習した方策。

| | sit_v1_best_S | **sit_soft_v2** |
|---|---|---|
| 座面ピーク荷重(0.70倍速) | 1089N = **体重の3.17倍** | **557N = 1.62倍** |
| 参照より沈む量 | 64 mm | **15 mm** |
| 完走(20シード) | 20/20 | 20/20 |
| 遅くできる限界 | 0.65倍まで | **0.30倍まで20/20** |

足した報酬(いずれも着座を含むモーションだけに効く。段差登りは不変):
- `r_zsit`(0.30)— 参照より**下へ沈まない**。★本命。実測で骨盤が参照より57〜76mm沈み、
  座面力0Nのまま −0.86m/s で落ちていた
- `r_seat`(0.30)— 座面荷重のうち体重を超えた分を罰する
- `r_vzsit`(0.20)— 参照より速く落ちる分を罰する
- `r_sit` の発動条件を修正 — 従来は膝角度で判定していたため、参照の骨盤がまだ座面の
  0.139m上にある段階(**0.90秒早い**)から尻の荷重を要求しており、**早く落ちるほど得**になっていた

> **罰は必ず線形にすること。** 最初 `exp(-x^2)` で書いたが、実測値(体重の3.2倍)では
> 完全に飽和して勾配が消え、学習が進まなかった。**2回同じ罠を踏んでいる。**

sit_soft_v2 は遅いほど荷重が下がる(0.70倍557N → 0.30倍456N)ので、
ゆっくり座らせたいならこちらを使う。

## 5.6 座り方式(内蔵 / 学習 / ハイブリッド)

| 方式 | 中身 | 実測 |
|---|---|---|
| 内蔵 | `SetStandHeight` だけ | ★椅子に届かない。旧FWは**下限0.56mで頭打ち**(実機10:30: 0.42m指令、code=0で受理されるのに0.56mまで。膝+14度=4cmのしゃがみが上限)。以前は到達確認をせず**偽成功**にしていた |
| **学習(現行)** | 方策のみ | 座れるが、開始時の中腰保持でトルク飽和(沈み111mm・飽和1.81倍 @16:18) |
| ハイブリッド | 内蔵で下限(0.56m)まで下げ→その姿勢で受け渡し→方策 | シム20/20完走・**座面ピーク0.69倍**。開始が座面に近く速度ゼロから始まるため |

ハイブリッドの流れ:
`prelower_builtin`(読み返しGET_STAND_HEIGHTが1.5秒動かなくなったら頭打ちと判定)
→ `enter_lowlevel`(静止待ち→latch→即Release)
→ `seek_start_frame`(実姿勢に最も近い参照コマ。距離は**サジタル(股P/膝/足P/R)のみ**で測る)
→ `retarget_ref_decay`(開始コマでオフセット100%→25コマ=0.5秒でゼロへ)
→ `run_policy`

★**定数ピン(従来のretarget)をそのまま使うとシム20シード全滅する**:
開始コマの股ヨー振れ(±19度)と腕の差(+56度)が着座姿勢まで歪むため。

### ★現状ハイブリッドは「学習」に戻されている(2026-08-26)
現実的ノイズ + 実機同等の行動EMA を入れた**正直なシム検証で16/20に低下**
(以前の20/20は同一ロールアウト×20の見せかけだった)。
検証スタンプ(`artifacts/hybrid_probe.json`)が無いため**ランナーが実機実行を自動ブロックする**。
`probe_hybrid.py` で全シード完走するまで実機に出さない。当面は `学習` を使う。

シムで踏んだ罠2つ(プローブ自体の教訓):
- 実姿勢はスネが参照より数cm後ろに張り出し、**椅子の土台に1〜2cmめり込む**配置になる
  → シムでは椅子から6cm逃がして参照座標も同量シフトして再現。
  **実機でも「椅子に背を向け適切な距離」の目視ゲートが今まで以上に効く**(近すぎるとスネが土台に当たる)
- 中止して hand_back した場合、**立位高さ設定は0.56mのまま残る**
  (次の実行前に「歩行モードへ戻す」で通常に戻す)

## 5.8 GPU移行調査(`docs/GPU移行_調査結果_20260816.md`)

RTX 3060 Laptop 6GB / 20コア / 31GB での実測。

**(1) 既定 `--envs 128` はこのPCで起動しない。**
`MotionImitationEnv.__init__` が環境ごとに `MjModel.from_xml_path` を呼び直すため
(MjModel 1個 = **235MB**、1ワーカー8環境で RSS 2.00GB、128環境で約32GB > 31GB → OOM)。
モデルをプロセス内で1個だけ持てば **RSS 2.00GB → 0.64GB**、
64環境2,045 steps/s → **160環境2,785 steps/s(+36%)**。

**(2) CPU側は物理律速。** 1イテレーション14.7秒の内訳は
ロールアウト14.5秒(方策0.80秒 / **環境待ち13.7秒**)+ GAE 0.03秒 + PPO更新0.2秒 = **91%が物理待ち**。
20コアで **3,000 steps/s あたりが天井**。
`timestep` を 0.002 → 0.003 にすると**既存方策が壊れる**(段差登り100%→0%)。

**(3) MuJoCo Warp は動くがシーン次第。** 4,096ワールドで5,386 steps/s(VRAM 413MiB)=CPUの2倍止まり。
同じGPUで **mjlab** の G1タスクは **37,000 env-steps/s(13倍)**。差はサブステップ数(10 vs 4)と
ソルバ設定、報酬・観測まで全部GPU上でバッチ計算していること。
※ `_setup_collision_filter()` を適用したモデルは mjwarp のCCDカーネル読み込みに失敗する

**(4) 学習アルゴリズム側で見つかった不備**
- ★**割引率 γ=0.97 が課題の長さを覆っていない**。50Hzでは実効ホライズン
  1/(1−0.97) = **33ステップ = 0.67秒**。課題は climb_hold 7.5秒 / sit_only 5.0秒。
  目安: γ=0.99→2.0秒 / 0.995→4.0秒 / 0.997→6.7秒 → **着座0.995 / 段差登り0.997**
- **観測に「前回の行動」が入っていない**のに報酬 `r_smooth` は前回行動に依存(非マルコフ)
- `train.py` のベスト保存基準 `score = mret/max(1,mlen)*mlen` は実質 `mret` と同じ
- 段差登りの段階B(押し外乱)が未実施。このPCで測り直すと 0.3m/sで**63%**、
  失敗はほぼ「上半身ロール12度超」の制約違反で転倒ではない

**(5) mjlab(2026-08-09 v1.6.0)導入済み。**
`Mjlab-Tracking-Flat-Unitree-G1` = BeyondMimic方式の全身モーション追従が最初から入っている。
**適応サンプリング実装済み**。参照モーションは npz を渡すだけで、50FPS前提が `CONTROL_HZ=50` と一致。

**注意**: 学習済み `.pt` は**そのままGPU側へ引き継げない**(観測・行動空間も物理刻みも別物)。
GPU側で学習したら必ず **CPU MuJoCo(このパッケージ)で評価し直す**
(「MJX特化の歩容になって別プラント転移が悪化した」実例あり)。
