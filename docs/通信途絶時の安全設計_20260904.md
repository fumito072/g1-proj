# 通信が切れたときの安全設計(2026-09-04 改訂)

## 何が起きていたか

UI(PC/スマホのブラウザ)のハートビートが 8 秒途絶えると、コックピットは**一律 DAMP
(kp=0)** にしていた。立っている機体・椅子へ降りている途中の機体が、通信の瞬断で突然
脱力して倒れる事例が出た。

「ネットワークは安全経路ではない」(docs/オンボード運用.md)のに、切れた瞬間に**最も
危険な操作(脱力)**をしていたのが誤り。制御は機体内で完結しており、通信が切れても
制御は止まらない。切れて困るのは「操作者が介入できないこと」だけ。

## 新しい振る舞い — 状態で分ける(`Engine._ui_loss_plan` / `_on_ui_lost`)

| 途絶時の状態 | 対応 | 理由 |
|---|---|---|
| **方策の実行中**(RUNNING: 着座・登り・旋回の途中) | **最後まで実行**し、完了後は方策で姿勢を保持(HOLD)。**完了後の自動移行(ダンプ/着座FSM)はしない** | 方策はバランス制御。途中で止める方法が無い(PD保持は数秒で倒れる、dampは即倒れる) |
| **方策で保持中**(HOLD / WAIT_CONFIRM で hold_pol あり) | そのまま保持。30秒ごとにモータ温度をログ | 座った姿勢・立位を方策が支えている |
| **方策なしのPD保持**(制御権だけ取った IDLE / 開始姿勢への補間中 MOVING / 立位待機) | **内蔵バランス制御へ返して静止**(UserCtrl 経路: `SwitchToInternalCtrl(LAST=0)` → 802 走行の静止立位 / ReleaseMode 経路: `SelectMode(ai)` → ロック立位 4)。damp はしない | PD保持にはバランスが無く数秒で倒れる。返す先の内蔵制御が「立っている途中でバランスを保って静止」を実現する |
| **内蔵歩行**(WALK:ready / WALK:auto / 十字キー) | 速度ゼロ(自動歩行は自分で中止、手動は0.5秒で失効)。内蔵バランスで静止 | 変更なし |
| **内蔵制御中**(STD:*) / DAMP | 何もしない | 内蔵制御が支えている |
| 補間(MOVING)が途絶中に終わった | 方策を始めず IDLE(現姿勢PD保持)にして、上の「内蔵バランスへ返す」に任せる | 操作者が見ていないのに方策を始めない |

**damp するのは従来どおり物理の異常だけ**: 傾き 40 度・関節速度・LowState 途絶(0.2秒)・
lowcmd 送信停止(50ms)・NaN・制御ループ例外・制御周期(実機のみ)・操作者の E-STOP。

UI が戻ると `UI(通信)復帰: 途絶 x 秒。途絶中の対応: …` をログに残し、画面上部に
黄色の帯で表示する(かんたん画面・詳細画面とも)。

## 実装の要点

- `real/real_robot.py` `return_to_balance()`: UserCtrl 経路では 7111(LAST=0) を**同期**で
  送り、返ってから送信を止める(先に止めると UserCtrl のまま指令が無い窓ができる)。
  FSM が 1000 以外になったことを 3 秒以内に確認する。2026-08-26 15:22/15:44 の実機で
  LAST 返却は往復とも崩落なし(docs/ポータブル版_設計メモ/09)
- `real/cockpit.py` `_watchdog`: 途絶の検知は従来どおり 100Hz の監視スレッド。処理は
  `_on_ui_lost`(冪等。RPC は `_spawn` でワーカーへ)
- `_do_after_phase`: 途絶中は完了後の自動移行(ダンプ/着座FSM)をしない
- `beat()`: 復帰の記録。`hbdrop`(詳細画面の「通信途絶を模擬」)で 20 秒間ハートビートを
  無視して、シムで手順を確かめられる

## 確認したこと(シムモック)

- 着座の実行中に途絶 → 395コマ走り切って HOLD、自動移行なし、DAMP なし
- 制御権だけ取った立位(PD保持)で途絶 → 内蔵バランスへ返却(sim では立位4の近似)
- 自動歩行中に途絶 → 速度ゼロで中止(test_autowalk.py 6)

## 実機で確かめること(ハーネス・E-STOP 必須)

1. 立位で [カスタム制御へ] → 有線を抜く(または端末の画面を消す)→ 8 秒後に
   「内蔵バランス制御へ返却(LAST): … FSM 802」が出て、機体が立ったまま静止するか
2. 着座の実行中に画面を消す → 最後まで座って、方策で保持し続けるか(自動ダンプしない)
3. 復帰後、画面の帯に途絶時間と対応が出るか

## 残る限界

- 方策の保持(HOLD)が長時間続くとモータが発熱する。温度はログに残るが自動では止めない
  (止める=脱力で、それが事故になる)。復帰したら操作者が [ダンプ] を押す。
  リモコンの L2+B(ダンピング)も常に効く
- 内蔵制御へ返す RPC が失敗したときは PD保持のまま(バランス無し)。ログに出るので、
  リモコンの L2+UP(ロック立位)/L2+B で引き取る
