# 自動歩行 — 前進(壁の手前で自然に停止・障害物は回り込み) / 横歩き(足踏み)(2026-09-04)

実装: `real/autowalk.py`(本体)、`real/cockpit.py`(UI と配線)、
`real/sim_robot.py`(運動学モックと合成LiDAR)、`real/test_autowalk.py`(机上試験)。

## 1. 何をするか

かんたん画面の [▲ 前進] = mode `forward`、[◀▶ 横歩き] = `side`、[左へ5cm][右へ5cm] = `side` の
5cm、詳細画面の [▶ 自動歩行 開始] = `both`(前進 → 横移動)。

```
FORWARD   内蔵歩行に前進速度を送る。IMUヨーで直進を保ち、オドメトリで経路線からの
          横ずれも補正する。LiDAR の前方コリドー(幅 0.7m・床から 0.12〜1.8m)の最近点までの
          距離 d を測り、**残り(d − 停止距離)に応じて段階的に減速**:
            ≥1.5m 100% / 1.0〜1.5m 80% / 0.6〜1.0m 55% / 0.25〜0.6m 35% / 0〜0.25m 15%(最低0.08m/s)
          加減速に上限(加速0.3・減速0.6 m/s²)を掛けて滑らかに。停止距離で停止(連続2回で確定)
          前方の物体の横幅を測り、**横幅 1.4m 以上か両側 1m 以上に広がる = 壁**(止まる)、
          それ以外 = 障害物 → 左右どちらかに体が通る幅(物体の端 + 肩幅0.35 + 余裕0.15)が
          空いていれば **回り込み**:
  DETOUR_OUT   空いている側へ横歩き(足踏みパルス)で経路線から e_t だけ離れる
  DETOUR_PASS  物体の奥 +0.6m まで 60% の速度で前進(横ずれは e_t に保持)。
               先に別の障害物が停止距離まで来たら中止
  DETOUR_BACK  経路線(横ずれ 0)へ横歩きで戻る → FORWARD を続ける(1回の前進で最大2回)
STOPPING  速度ゼロで 1.2 秒静定
SIDE      **足踏みパルス**: 0.5秒動いて 0.4秒止まって測る、を繰り返す。残り距離に応じて
          パルスの速度(0.08〜0.15m/s)と長さを縮めるので、5cm 単位の微調整ができる。
          到達許容 2cm。進行方向 0.45m 未満に点があれば中止
DONE      速度ゼロ(3回送信)。結果を イベント.log と walk_*.jsonl に残す
壁が無いまま「最大前進距離」に達したら止まる(both では横移動もしない)
```

方策(rt/lowcmd)は使わない。**内蔵の歩行 FSM(802。だめなら501)に
`SetVelocity(vx, vy, ω, duration=0.5)` を 10Hz で送るだけ。** バランスは内蔵制御。

## 2. パラメータ(UI の「5. 歩行」欄。`walk_param` で機体へ送る)

| 名前 | 既定 | 範囲 | 意味 |
|---|---|---|---|
| 速度 `v_fwd` | 0.35 m/s | 0.05〜0.9 | 前進の巡航速度。十字キーの前進上限も兼ねる |
| 停止距離 `stop_dist` | 0.60 m | 0.3〜2.5 | 壁(障害物)のこの手前で止まる(骨盤基準) |
| 横移動 `side_dir` / `side_dist` | 左 / 0.50 m | 0.02〜3.0 | 向きと距離 |
| 最大前進 `max_fwd` | 4.0 m | 0.3〜10 | 壁が無いときの安全上限 |
| 回り込み `avoid` | on | | 壁以外の障害物を回り込む |
| ドライラン `dry_run` | off | | on なら**速度を一切送らず**判断とログだけ(距離表示の確認用) |
| (固定) `v_side` / `v_creep` | 0.15 / 0.08 m/s | | 足踏みパルスの上限 / 忍び足の最低速度 |
| (固定) `wall_width` | 1.4 m | | 前方の物体の横幅がこれ以上なら壁 |
| (固定) `detour_margin` / `detour_max` | 0.15 / 0.9 m | | 回り込みの余裕 / 最大横オフセット(超えるなら壁扱い) |
| (固定) `side_tol` / `pulse_on` / `pulse_off` | 0.02 m / 0.5 s / 0.4 s | | 横歩きの到達許容 / 足踏みパルスの動く時間・止まる時間 |
| (固定) `half_w` | 0.35 m | | 前方コリドーの半幅。肩幅 0.45m に余裕 |
| (固定) `h_min`/`h_max` | 0.12 / 1.80 m | | 床からこの高さ帯の点だけを障害物とみなす |
| (固定) `side_clear` | 0.45 m | | 横移動中に進行方向の空きがこれ未満なら中止 |

固定のものは `autowalk.WALK_DEFAULTS` を書き換えるか、`walk_param` に JSON で渡せる。

## 3. センサと座標系

| 入力 | トピック | 読み方 |
|---|---|---|
| 点群 | `rt/utlidar/cloud_livox_mid360`(PointCloud2、10Hz) | **ポーリング**(20Hz)。ハンドラは付けない(docs/オンボード運用.md §3) |
| オドメトリ | `rt/odommodestate`(unitree_go SportModeState_、約500Hz) | ポーリング(20Hz)。position[0:2] と imu_state.rpy[2] |
| ヨー | LowState の IMU rpy[2] | 直進保持と点群の体基準化 |

点群の座標系は **header.frame_id で自動判別**する:

- `odom`/`map`/`world` を含む → 世界座標。オドメトリ位置と IMU ヨーで体基準へ回す
  (旧コックピットの現場メモ「odom座標系の点群は base位置+IMU yaw で体基準に変換すること」
  に従う。オドメトリが来ていなければ**判定不能=前進しない**)
- それ以外(`livox_frame` 等) → センサ座標。x前・y左とみなし、センサ→骨盤 0.10m を足す

どちらでも**床平面を点群からフィット**して「床からの高さ」を出すので、z=0 がセンサ
なのか床なのかに依存せず、センサが下向きに傾いていても水平化される(机上試験で、
傾き10度・高さ1.15m のセンサ座標でも前方距離 1.20m を ±0.02m で再現)。

UI の「歩行」欄に **座標系 / 床の高さ / 前方距離 / 点数 / LiDAR・odom の鮮度** が常に出る。
[LiDAR読取 開始] を押すと、歩行モードに入らなくても表示だけ確認できる。

## 4. 止まる条件(自動歩行の中で見ているもの)

| 条件 | 動作 |
|---|---|
| 障害物が停止距離以内(連続2回) | 前進を止め横移動へ(本来の動作) |
| 最大前進距離に到達 | 停止して終了(横移動なし) |
| LiDAR が 1.5 秒途絶 / オドメトリが 0.8 秒途絶 | 中止(速度ゼロ) |
| 判定不能(床が取れない・点が少ない) | その場で待機(速度ゼロ)。回復すれば続行 |
| 体幹の傾き 25 度超 | 中止(速度ゼロ) |
| UI ハートビート途絶(8秒) | 中止(速度ゼロ) |
| 横移動中、進行方向 0.45m 未満に点 | 中止(速度ゼロ) |
| 時間切れ(前進: 最大距離/速度×2+15秒、横: 距離/速度×3+10秒) | 中止 |
| [■ 歩行停止] / 画面下の 歩行停止 | 中止(速度ゼロ)。**HTTPスレッドから直接**(キューを通らない) |
| E-STOP | damp(既存どおり)。★歩行中に押すと倒れる。まず[歩行停止] |

**止め方は全部「速度ゼロ」であって damp ではない。** 歩行中に damp を送ると倒れる。
内蔵バランスに立たせたまま止める。送信は `VelSender` の1スレッドだけで、指令が 0.5 秒
更新されなければ自動でゼロを送る(こちらのプロセスが固まっても `duration=0.5` で
機体側が止まる)。

方策の実行が始まると(`_begin_phase`)、LiDAR/オドメトリの読み取りは止め、自動歩行も
止める(機体では GIL の取り合いが制御周期に直接効く)。

## 5. ログ

- イベント.log: 開始パラメータ / 障害物検出 / 横移動開始 / 結果(完了・中止理由)
- `logs/real/<session>/walk_YYYYmmdd_HHMMSS.jsonl`: 100ms 毎の

## 6. 実機での検証手順(この順で。飛ばさない)

前提: 平らな床・周囲 3m 以上空ける・ハーネス・リモコンの E-STOP を握る・AC不要(オンボード)。

```
A. 距離表示だけ(機体は動かさない)
   [立つ] → [LiDAR読取 開始] → 画面の「前方」を見る
   ・何も無いとき ---(None) になるか
   ・1.0m 前に段ボール箱(高さ 0.5m 以上)を置いて 1.0±0.15m と出るか
   ・0.5m まで近づけて赤くなるか(停止距離 0.6m)
   ・「座標系」が world / sensor のどちらで出たかを記録する(frame_id の実測)
   ・床の高さが妥当か(world なら ≈0、sensor なら ≈1.1〜1.2m)
   ★ここが合わなければ先へ進まない。人が前に立っても検出されるが、
     膝より低い物(0.12m 未満)は見えない仕様

B. ドライラン
   [歩行モードへ(802)](★接地・E-STOP)→ ドライラン on → [▶ 自動歩行 開始]
   ・機体は動かない。「送信 (0, 0, 0)」のまま phase が FORWARD で
     待機し、時間切れで中止になるのが正常(前進しないのでオドメトリが進まない)
   ・イベントログに開始パラメータと座標系が出ることを確認

C. 十字キー(手動)
   ・前 を 1 秒だけ押す → 1 歩前進して止まる(離して 0.5 秒以内)
   ・左 / 右 / 旋回 も同様。★十字キーの操作感で速度を決める(既定 0.35)

D. 自動歩行(短距離)
   最大前進 1.5m・停止距離 0.8m・横移動 0.3m・速度 0.3 → 1.0m 先に箱
   ・0.8m 手前で止まり、1.2秒後に横へ 0.3m 動いて止まるか
   ・イベントログの「前進 x.xx m」がメジャーの実測と ±0.1m で合うか(オドメトリの確認)
E. 既定値で(停止距離 0.6・横 0.5・速度 0.35)
```

各段で1つでも想定と違えば止めて、`walk_*.jsonl` と イベント.log を持ち帰る。

## 6b. 実機での確認(2026-09-04、有線で本体へ配備して起動)

- `rt/odommodestate` は届く(遅れ 10〜50ms、位置・ヨーが読める)
- **`rt/utlidar/cloud_livox_mid360` は配信されていない。** DDS の配信一覧(91トピック)に
  `rt/utlidar/*` が1つも無く、Jetson 上に LiDAR ドライバのプロセスも無い。
  Livox Mid-360 自体は 192.168.123.120 に居て ping は通る。この FW(1.5.3.8)では
  点群の配信は別サービス(`rt/api/slam_operate` など)の起動が要るか、旧コックピット
  (2026-08-07)の時点とは配信の仕組みが変わっている。
  → 同日、**`real/lidar_bridge.py`** を追加した。機体に入っている Livox SDK2
  (`/usr/local/lib/liblivox_lidar_sdk_shared.so`)を ctypes で直接叩き、点群を
  `/dev/shm/g1_lidar.npy`(float32 N×4)+ `g1_lidar.json` に 10Hz で書く。
  `start_onboard.sh` が起動し、コックピットの LidarReader は DDS と /dev/shm の両方を見る。
  実測: 2083 パケット/秒、1コマ 1.4 万点、**センサは上下逆さに取り付けられていて
  (床法線が −z)、床からの高さ 1.27m、傾き 3.5度**。ブリッジが床平面を推定して
  「z=上、x=床が見える向き」に回した `livox_level` 座標で書く。
  ★x の向き(前/後)は床の点の平均方向から決めている。実機で人が前に立って「前方」の
  距離が出なければ `real/lidar_mount.json` に `{"yaw_offset_deg": 180}` を置いて反転する
- **[◀▶ 横歩き]・5cm・[▼ 後ろへ]・十字キーはオドメトリだけで使える**(横・後ろの障害物は
  見ないので操作者が目で見る)。[▲ 前進] は LiDAR が要る(ブリッジ起動後は使える)


### 6b-2. 実機の点群で分かったこと(2026-09-04 午後、機体上で確認)

### 6b-3. 細かい移動は「小刻みステップ」に作り替えた(2026-09-04 午後)

**実機の結果**: かんたん画面の [▼ 後ろへ5cm] を 802 で押した記録(`walk_20260904_114706.jsonl`)は、
vx=−0.08 m/s を 0.5 秒動/0.4 秒止のパルスで 13 秒送ってもオドメトリの進みが 0.000 のまま
(時間切れ)。**弱く短い速度指令では内蔵歩行が一歩も出ない**。

**新しい方式(`AutoWalk._step_axis`)**: 横歩き・5cm 微調整・後退・[1歩] のすべてが同じ機関を使う。

| 手順 | 中身 |
|---|---|
| 1歩の指令 | `step_v`(既定 0.20 m/s。画面の「強さ」弱0.15/中0.20/強0.30)を `step_on`=0.6 秒 |
| 着地を待つ | `step_off`=1.0 秒、速度ゼロ。その間もヨー保持・横ずれ保持は続ける |
| 測る | オドメトリでその歩の移動量を出し、**1歩の推定**(既定 6 cm)を実測で更新(EMA) |
| 刻む | 残りが 1歩の推定より小さければ指令時間を縮める(最短 `step_min_on`=0.3 秒)。残りが許容 2 cm 以内で到達。半歩未満の行き過ぎは追わない(往復して椅子や壁に近づかない) |
| 止まる | 横: LiDAR で横 0.45 m 以内に物があれば止める。前へ 1 歩: 停止距離+5cm 未満なら出さない。後ろ: LiDAR の死角なので操作者の目 |
| 歩かないとき | **3 歩で 1 cm も進まなければ中止**し「歩行モードが速度指令に応じていない」と出す(= 802 で SetVelocity が効かない場合の切り分け) |

- 前進の忍び足 `v_creep` も 0.08→**0.12 m/s** に上げた(不感帯の下で壁の手前で止まり切れなくなるのを防ぐ)。
- シムモック(`sim_robot.py`)に実機の癖を入れた: |v|<0.10 m/s・|ω|<0.15 rad/s は動かない、歩き出しに 0.25 秒。
  机上試験(`test_autowalk.py` §5)は 横 0.5 m(6 歩)/右 5 cm/後ろ 10 cm(2 歩)/1 歩/弱い指令で中止、を通す。
- かんたん画面: 「小刻みステップ」の行に 強さ・**1歩≈x cm(前回 y cm、n 歩)** の表示、[◀ 左へ1歩][▼ 後ろへ1歩][右へ1歩 ▶]。
  `walk_go` の JSON は `{mode:"step", dir:"left|right|back|fwd"}`。

**実機で確かめる順(操作者立ち会い、機体の周り 1 m を空ける)**:
1. [歩行モード](802) → 「強さ 中」で **[右へ1歩]**。機体が一歩出て、画面の「前回 x cm」が 3〜10 cm になれば OK。
   0 cm のまま「応じていない」と出たら 802 で SetVelocity が効いていない → 強さを「強」にして再試行。
   それでも動かなければ、歩行フェーズを 501 で行う設計へ変える(未実装。この文書に追記する)。
2. [左へ1歩] で戻す。次に [後ろへ1歩](後ろに椅子が無い場所で)。
3. [左へ5cm] / [右へ5cm]、[▼ 後ろへ5cm] を試す。1 歩目は推定 6 cm で指令時間を決めるので、1 歩が 10 cm を超える機体では
   最初の 5 cm 指示が行き過ぎることがある。その場合は「強さ 弱」にする。
4. 横歩き 0.5 m → 前進(壁の手前で停止)の順(§6 の B〜E)。


### 6b-4. 「正面の壁までの距離」の測り方を作り直した(2026-09-04 午後、操作者の指摘)

操作者の報告「LiDAR の距離が正しく出ていない」。調べると、**前後が逆**だった可能性が高い。

| 何が悪かったか | 直したこと |
|---|---|
| ブリッジの「前方」= 床が見える向きの平均。部屋の物で起動ごとに 6〜30° 変わり、頭の LiDAR は足が前に張り出すぶん**後ろの床の方が見える**ので後ろを向きやすい | 前方 = **生座標の +X 軸**を床面へ射影(取り付けは固定なので毎回同じ)。切替後の実測: 前 3.20 m(壁の面)・後 0.65 m — 以前「前 0.55〜0.69 m の壁」と出ていたものは後ろの壁/椅子だった |
| 距離の基準がセンサ +0.10 m(骨盤)で、機体の前面から測る実物より 25 cm ほど大きい | **つま先基準**(`front_offset`=0.15 m。センサ軸→つま先) |
| コリドー内の最近点なので、手前の物(机の脚・人)を壁と呼んでいた | **壁の面を RANSAC の直線で当てる**(`fit_wall`: 前方 ±1.2 m・h 0.25〜1.6・進行方向に ±35° 以内で垂直な面、内点が最大の 70% 以上ある候補のうち**いちばん手前**)。画面の大きい数字は壁の面までの距離(斜めなら角度も)。手前に物があれば「手前 x m に障害物 — 止まるのはこちら」を別に出す。停止判定は今までどおり手前の最近点 |
| 床平面の推定が机や段差の天面に乗って 8〜15° 傾いた | 法線が z_raw から 20° 以内・センサ高さ 0.9〜1.6 m の面だけを候補に。60 秒ごとに再推定(内点が 2 割増えれば差し替え)。検出器側は毎コマ床を当て直して傾きを吸収するので、ブリッジの傾き誤差は距離にほぼ効かない(cos) |

### 6b-8. 「もたつく・壁の前で足踏みのまま居座る」の原因と対策(2026-09-04 夕、実機ログ)

14:08〜14:10 の走行ログ(`walk_20260904_1408*.jsonl`)で、**指令した速度と実速度(オドメトリ)**を比べた:

| 指令 [m/s] | 実速度 [m/s] |
|---|---|
| 0.50 | 0.15〜0.20 |
| 0.42 | 0.13 |
| 0.35 | 0.08 |
| 0.20 | 0.04 |
| 0.15 | 0.02 |

実速度 ≈ **0.4 ×(指令 − 0.10)**。0.2 以下の指令はほぼ足踏みだけになる。速度プロファイルの最低速度 0.15 を
出し続けると、壁の手前で「足踏みのまま進まない」= 居座り(14:09 の走行は 40 秒の時間切れ)。
さらに前回入れた ContinuousGait(足踏み継続)がそれを強めていた。

対策:
1. **速度の較正層 `VelCalib`**: 望む実速度 → 指令 = 不感帯 0.10 + v/k(k の初期値 前後 0.45・横 0.35)。
   歩行中に (指令, 実速度) の 1 秒窓から k を実測で更新し、`real/walk_calib.json` に残す(次回も使う)。
   速度プロファイル・横歩き・小刻みステップは「望む実速度」で考え、指令はこの層が作る。
2. **最後の一歩 `_final_approach`**: 目標まで 25 cm 以内は、残り距離を較正モデルで指令時間に換算した短い歩き
   (指令 0.40 前後)→ 止めて測る、を最大 4 回。小さな指令を出し続けない。到達判定 5 cm。
3. ContinuousGait は既定 OFF(指令ゼロで自然に立ち止まる)。
4. **LiDAR ヨーの自動較正は既定 OFF**: 壁が主な景色だと壁沿いの平行移動が決まらず、13:3x〜14:1x に
   −4°〜−37° の間で暴れ、壁までの距離が 0.7→2.7 m に飛んで歩き続ける原因になっていた。
   `lidar_mount.json` の yaw_offset_deg は 0 に戻した。

シムモックにも同じ非線形(実速度 = 0.4·(指令 − 0.1))を入れ、机上試験を通した。
歩幅・歩数そのものは内蔵制御が速度指令から決める(SDK に直接の API は無い)。`SetSpeedMode`(−1/0/1/2)で
歩容の速さの段が変わる可能性があるので、実機で 1 を試す価値がある(`walk_param` {"speed_mode":1})。

### 6b-10. 「歩かせるたびに後ろへ進む量が増える」→ 学習を止め、歩き出す閾値未満の指令を出さない(2026-09-04 夕)

原因の見立て:
- 速度係数の実測更新(学習)が歩くたびに係数を大きくし(0.45 → 0.68 …)、同じ望む速度に対する**指令が小さく**

  減速中・物体へ寄せる場面(望む速度が最低の 0.15 になる)ほど指令が小さく、後退に見えた。
  ハーネスの張力が後ろ向きに掛かっていれば、この揺り戻りはさらに大きくなる。

対応:
1. **学習を既定 OFF**(`calib_learn=False`)。係数は固定(前後 0.45・横 0.35・不感帯 0.10)。`walk_calib.json` は
   読まず、機体の既存ファイルも削除した。

   止めるときは 0。中間の「歩かない・揺れるだけ」の指令を出さない。
3. 最後の寄せ(35 cm)は §6b-9 のとおり一定の遅い歩きで進み、残り 8 cm で一度だけ止め、戻さない。

ハーネスの有無で差が出るのは主に「歩き出し」と「止まり際」なので、上の 2 点(閾値未満を出さない・止め方を
一度にする)で吸収する設計。それでも後退が残る場合はログの「停止後 3 秒の位置変化」を見て、
`cmd_min_walk` を 0.35 に上げる(`walk_param` {"cmd_min_walk":0.35})。

(指令 0.30)に入った時点でもオドメトリの実速度が 0.4 m/s 前後あり(0.6 m の区間を 1.1 秒で通過)、
**速いまま止めた**ため内蔵歩行の停止動作(踏ん張り・後ろへの踏み出し)が大きく出た。指令 0.9→0.30 への
下げ幅も急(0.5 秒)だった。

対応:
- 減速の見込みに**オドメトリの実速度**(EMA)を使う。応答遅れの見込み 1.5 s、減速度 0.12 m/s²
  (0.35 m/s なら 0.5 + 0.5 = 約 1.0 m 手前から落ち始める)。望む速度の下げ幅の上限 0.25 m/s²(急に下げない)。
- 最後のゆっくり歩き(0.6 m)へは**実速度が 0.15 m/s 以下**になってから入る(`v_enter_final`)。
- 止める順: 0.20 を 0.3 秒 → 0 → **実速度 0.03 未満が 1 秒続くまで待つ**(最大 4 秒。止め際の足踏みが終わるのを
  待つ)→ ロック立位(FSM 4)。切替後に FSM を読んで確認し、4 でなければ 1 回やり直す。
- 停止後 3 秒の変化を、オドメトリ(前後・横)と **LiDAR の壁までの距離**の両方でログに出す
  (FSM 切替でオドメトリが飛ぶ可能性の切り分け)。

机上試験(モック)では停止後の変化 ±1 cm。実機では「壁までの距離 a→b m」が変わらなければ止まっている。


### 6b-14. 根本の見直し(2026-09-04 夕): FSM 4 は 200 から入れない → 802 で静止、壁の距離は LiDAR を真とする、歩行モードは 200 を先に

15:38〜15:39 の走行ログ:
- `ロック立位の切替: まだ FSM 200(試行 1/2)` — **SetFsmId(4) は 200 から受け付けられない**(応答 0 でも FSM は変わらない)。
  だから止めても歩行制御が動いたままで、足踏み → 後退が続いた。
- `壁 1.019m 手前で止まりました(停止距離 0.60m)` — 最終接近の残りをオドメトリで測っていた。オドメトリ(脚の運動学)は
  **足踏みも距離に数える**ので、実際には進んでいないのに「到達」した。
- 歩行モードに入るのに 6 秒かかっていた = 最新 SDK の Start()=SetFsmId(500) を先に試して 6 秒待ち、無反応で 200 に落ちていた。

この FW と SDK の関係(調査):
- 機体の Python SDK は `unitree_sdk2_python` 2026-02-26 版(pip 1.0.1)。GitHub 最新の `Start()` は 500 だが、**当機の FW は 500 に
  応答せず 200 で歩行に入る**(9/3・9/4 の全実測)。7110/7111(UserCtrl)・802(走行29dof)は通る。つまり SDK が新しく FW が

  変わりうるので、着座の経路(4→802→7110)の再検証が要る。
- 802 は「速度指令を受けない歩行制御の立位」(14:0x 実測: SetVelocity を送っても動かない / 9/3: 200・501・4 から 0.4 秒で入り、
  0.4〜0.8 秒で関節速度 0.1 rad/s 未満に静止)。**目的地で足踏みをやめる状態として使える**うえ、着座(7110)の入口でもある。

設計の変更:
1. 歩行モードは **200 を先に**試す(待ち 3 秒)。500 は後回し。
2. 壁への最終接近と静止の判定は **LiDAR の前方距離**で行う(オドメトリは LiDAR が取れないときだけ)。実速度の見込みも
   LiDAR の距離の減りから取る。
3. 目的地で止めたら(0.20×0.3 s → 0 → LiDAR で静止 1 秒を確認)**802 へ切り替える**(`enter_standing_loco`。FSM を読んで確認、
   再試行 1 回)。次の [前進]/[横歩き] は 802→200 を直接試し、だめなら 4 経由で歩行へ戻る。
4. 止まった後は LiDAR が途切れても中止しない(15:39 の「LiDAR途絶」中止の対策)。


### 6b-15. いちからの設計(2026-09-04 夜、調査に基づく。機体で未検証)

操作者の指示「最新の SDK・他の実装例・リモコンの歩く/止まるを参考に、目的の距離まで歩いて止まるだけをいちから」。
機体を触らず、調査(6 エージェント: SDK の Python/C++ master とコミット履歴、公式ドキュメント en/zh、GitHub issue、
コミュニティ実装)の一致点だけで設計した。

**調査で確定したこと**(出典は docs/歩行SDK調査_20260904.md)
| 項目 | 内容 |
|---|---|
| FSM(公式表) | 0 ゼロトルク / 1 ダンプ / 2 スクワット / 3 座る / 4 ロック立位(以上バランス制御なし)/ 706 / 702 / **500 通常運控(腰1DoF)** / **501 通常運控 腰3DoF(29DoF 機はこちら)** / **801 走跑(29DoF・ai_sport 8.6 以降は 802 と読める)**。200 は表に無い(2026-04 まで SDK の Start() だった旧番号。当機はこれで歩行に入る) |
| 802 | **走跑(Run)モード**。SetVelocity(7105)を受けない(issue #170 と当機の実測が一致)。UserCtrl(7110)の入口としてだけ使う。**静止用に使うのは誤り**(15:4x に入れたのは取り消し) |
| 足踏み | 速度ゼロで足踏みを**止めるか続けるかは SetBalanceMode(7102)**: 0 = 静止立位(BalanceStand、リモコン START 単押し)、1 = 足踏み継続(ContinuousGait、START 二度押し「非推奨」)。歩行 FSM に入って静止してから一度だけ 0 にし、GetBalanceMode(7003)で確認 |
| 止まった判定 | **GetFsmMode(7002) == 0**(静止)。1(動作中)の間は多くの FSM 切替が拒否される(SetFsmId(4) が効かなかった理由)。fw ≥ 1.5.1 なら rt/sportmodestate.fsm_mode も同じ |
| SetVelocity | {"velocity":[vx,vy,ω],"duration":d}。最新の指令が前の指令を置き換え、duration を過ぎると内蔵が自動停止(デッドマン)。値は内蔵が許容範囲に切り詰める(0.32 m/s 頭打ちの候補: リモコンの低速モード L2 二度押し。高速は L1 二度押し)。SetSpeedMode(7107)は 0..3 = 1.0/2.0/2.7/3.0 m/s で**走跑モード向け** |
| 4 への切替 | 走行中(fsm_mode 1)は拒否。公式の起動順は ダンプ→ロック立位→運控。**走行から 4 へ戻す経路は無い** |
| オドメトリ | 脚の運動学。足踏みも距離に数える(壁 1.02 m で「到達」した原因)。距離は LiDAR、オドメトリは向きと横移動だけ |
| 後退の偏り | 公開情報に無し。候補: 止め際の速度が高い(踏ん張り)+リモコンに保存された**前後オフセット補正**(R1+X/Y で R1+↓/↑)。SDK に相当機能は無いので、リモコンで一度確認・解除する |

**設計(real/autowalk.py を書き直し)**
1. 歩行モード: ロック立位(4)から **SetFsmId(501)** を 0.5 秒ごとに送り直して GetFsmId で確認(立ち上がり中は捨てられる)。だめなら 200。500 は送らない。静止(fsm_mode 0)を待って **SetBalanceMode(0)**、読み返して確認。走跑(802)に居るときは戻せないので「ダンプ→スタンドロック→歩行モード」を案内。
2. 前進: 指令 = k(0.9) × (LiDAR の残り距離 − 停止距離)を **[下限 0.30, 上限「速さ」0.5/0.7/0.9]** に収める。下限未満は出さない(足踏みだけになる)。上げ幅 0.6・下げ幅 0.5 m/s² で滑らかに。10 Hz、duration **0.3 s**(送信が止まれば内蔵が 0.3 秒で止める)。
3. 停止: 残りが **stop_lead(0.15 m)以下**を 2 コマ見たら指令ゼロ。ゼロを送り続けながら **fsm_mode == 0 が 1 秒続く**まで待つ(最長 6 秒)。FSM は切り替えない。止まってから 3 秒後の LiDAR 距離とオドメトリの変化をログに出す(「停止: 指令ゼロ時 d0 → 静止 d1 → 3秒後 d2」)。この数字で stop_lead を合わせる。
4. 斜めの壁: 8° 超はその場で回転してから、以下は歩きながら壁の法線に向きを寄せる(前と同じ)。
5. 回り込み: 壁でない物体が 1.5 m 以内なら歩きながら横に寄せ(余白 8 cm)、通り過ぎたら戻る(前と同じ考え。指令の作り方だけ新方式)。
6. 横歩き・後退: オドメトリで残りに比例した指令(下限 0.30・上限 0.5)、到達したら同じ停止手順。10 cm 以下の微調整だけ 1 歩ずつ。
7. 捨てたもの: 速度較正と学習、最終接近(短い指令の繰り返し)、アンカー保持、ロック立位/802 への切替、ContinuousGait、ヨー自動較正(既定 OFF のまま残す)。

**実機で最初に確かめること(立ち会い)**
- [歩行モード] のログに「歩行 FSM 501 に到達」と「静止立位モード SetBalanceMode(0) → 読み返し 0」が出るか。読み返しが「未対応」なら、この FSM では 7102 が効かない(200 の場合)。そのときはリモコンで START を単押し(静止立位)にしてから試す。
- リモコンで前後オフセット補正が入っていないか(R1+X/Y 中に R1+↓/↑)、低速モード(L2 二度押し)になっていないか。
- [前進] 1 回: 「停止: 指令ゼロ時 → 静止 → 3秒後」の 3 つの距離。d0 と d1 の差が行き過ぎ、d1 と d2 の差が止まった後の流れ。
